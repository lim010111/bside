## 해커톤 맥락에 맞춘 구성

[해커톤 안내](../docs/hackathon-brief.md)의 주제는 교류이며, 문제 해결력·AI 활용·MVP 완성도·사업화가 평가 대상입니다. README는 다음 질문에 순서대로 답하도록 작성했습니다.

1. **어떤 서비스인가?** 같은 공간에서 지금 대화할 만한 사람을 찾도록 돕습니다.
2. **어떤 문제를 푸는가?** 상대의 경험과 현재 교류 의도를 몰라 첫 대화를 시작하기 어려운 상황을 다룹니다.
3. **어떻게 쓰는가?** 입력 → 주변 발견 → 추천 이유 → 1:1 대화 → 대화 유지 흐름과 가상 사례를 제시합니다.
4. **AI가 왜 필요한가?** 자유로운 표현의 자기소개·의도에서 공통점과 도움을 주고받을 접점을 평가합니다.
5. **누구에게 가치가 있고 누가 비용을 내는가?** 참여자의 효용과 운영자의 구매 동기를 연결하고 도입 단위·과금 방식·비용 요인을 설명합니다.
6. **어디까지 동작하는가?** 실기기·운영 배포·모듈 성능의 검증 범위를 각각 연결합니다.
7. **어떻게 실행하는가?** 화면 데모, 실제 서버, Android 실행 경로를 제공합니다.

## 시장 주장을 위해 확인한 1차 자료

| 공식 자료 | 확인한 내용 | README에서의 용도 |
| --- | --- | --- |
| [Brella 제품 소개](https://www.brella.io/) | 행사 네트워킹 제품이 참여자의 관심사·목표에 따른 의도 기반 AI 매칭을 소개합니다. | AI 매칭의 존재 자체를 차별성으로 주장하지 않고, Bside의 근접 발견·현재 의도·대화 흐름을 설명합니다. |
| [Donut 요금 안내](https://www.donut.com/pricing/) | 조직용 연결·참여 도구에 유료 구독과 조직별 청구 모델이 있습니다. | 운영 조직을 구매자로 두는 가설의 참고 사례로 사용합니다. |

이 자료는 Bside의 유료 수요, 가격, 시장 점유율, 수익성을 입증하지 않습니다. Bside의 상품·과금 방식·초기 진입 경로는 검증할 사업화 제안으로 명시했습니다. 이전 시장 조사에 있던 통계·경쟁사 가격·1인당 원가를 재사용하지 않았습니다.

## 현재 사실과 맞추기 위해 확인한 자료

- 제품 흐름은 [현재 제품 결정](../docs/product-direction.md), [공통 용어](../CONTEXT.md), 실제 웹·Android·서버 코드와 대조했습니다.
- 실기기 발견·채팅은 [Android 검증](../android/README.md#검증), 운영 주소의 추천·푸시 수신은 [최신 배포 기록](../docs/deployment.md#확인된-것)을 근거로 삼았습니다. 예전 README에 남은 미검증 표기는 최신 기록으로 갱신했습니다.
- 추천 지연은 [최신 실모델 전후 비교](../server/docs/ai-latency-ab.md)의 측정 경계·표본 수·실패 결과를 함께 옮겼습니다. 서버 내부 처리 시간을 사용자가 보는 전체 지연으로 표현하지 않았습니다.
- 구성도는 [기존 서비스 구성도](../docs/assets/bside-service-architecture.png)를 확인해 재사용했습니다. 과거 행사 방 기반 화면 캡처는 현재 사용 흐름과 달라 넣지 않았습니다.
- 사용자 효용·시장성은 파일럿에서 측정할 대상으로, 운영자용 유료 기능은 후속 개발 대상으로 표현했습니다.
