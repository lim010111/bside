# 검증 기록

마지막 실행: 2026-09-19 · 브랜치 `codex/frontend-improvements`

테스트와 빌드가 통과했다는 사실만으로 제품이 동작한다고 적지 않는다. 아래는 실제로 실행해서
확인한 것과, 아직 확인하지 못한 것을 나눠 적은 기록이다.

## 실행한 명령과 결과

| 명령 | 결과 |
| --- | --- |
| `npm run lint` | oxlint 경고·오류 0건 |
| `npm test` | 29개 통과, 실패 0건 |
| `npm run build` | 성공. `mock.js`와 예시 참가자 데이터가 번들에 포함되지 않음 |
| `npm run build:demo` | 성공. `dist-demo/`에 `mock.js` 청크 포함 |

`npm run build` 출력에 `mock` 청크가 없다는 점이 "배포 빌드는 데모 데이터를 싣지 않는다"는
근거다. 이 두 빌드를 함께 돌려서 매번 비교한다.

## 데모 추천이 실제로 나오는지

계약 테스트가 전부 통과하는데도 추천이 한 명도 나오지 않던 구간이 있었다. `reason()`이
`막혔|막혀`만 보고 `막힌`을 빠뜨려서, 씨드 45명의 교류 의도 4종이 전부 첫 관문에서 걸렸다.
**씨드 1,980쌍 전부가 탈락해 추천은 항상 0명이었다.** 계약이 맞는지와 결과가 나오는지는
다른 질문이라는 걸 여기서 배웠다.

고친 뒤 실제로 세어본 값이다. 목 API를 노드에서 그대로 돌려 측정했다.

| 측정 | 값 |
| --- | --- |
| 씨드 45명을 각각 참가자로 대입했을 때 추천을 받은 사람 | 36명 |
| 한 사람이 받는 추천 수 | 최소 0 · 중앙값 3 · 최대 15 · 평균 3.4 |
| 화면 placeholder 문구로 입장했을 때 | 5명 |

추천 0명인 9명은 `꼭 정해진 주제 아니어도 편하게 대화할 사람이면 좋아요` 계열로 교류 의도가
비어 있는 참가자다. **이 경우 추천을 비워두는 것이 맞는 동작이다.** 목록에는 그대로 보인다.

`tests/mock.test.js`가 이 값을 지킨다. 어간 하나를 도로 빼면 테스트가 실패하는 것까지
확인했다(`막히|막힌`을 제거 → 28번 실패, 되돌리면 통과).

**이 추천기는 규칙이지 모델이 아니다.** 발표와 질의응답에서 모델이 판단했다고 말하지 않는다.

## 브라우저에서 눌러본 것

개발 서버(`npm run dev`)를 375×812 모바일 뷰포트에서 확인했다.

- 입장: 닉네임·자기소개·교류 의도 입력 후 참여 → 참가자 목록(45명)으로 이동
- 목록: 검색 입력, 참가자 카드, 추천 상태 안내가 함께 표시됨
- 상세: 자기소개·찾는 사람·추천 이유 영역 표시. 추천 이유가 없으면 안내 문구로 대체됨
- 채팅: 메시지 전송 후 말풍선 렌더링, `localStorage`에 대화 1건 생성
- 새로고침: `#chat/{id}`로 다시 들어가면 보낸 메시지가 그대로 복원됨
- 화면에 데모 배너나 저장 방식 안내 문구가 없음을 확인함

레이아웃은 `.screen-chat` 높이가 뷰포트(812px)와 일치했다. 채팅 입력창 아래 여백은 미리보기
패널의 레터박스이지 앱의 레이아웃 문제가 아니다.

주의: 자동화 도구로 보낸 합성 클릭·키 입력은 일부가 대상 요소에 전달되지 않았다. 이때는 앱이
아니라 입력 전달이 문제였고, 실제 이벤트가 요소에 도달하면 Enter 전송과 버튼 이동 모두
동작했다. 자동화 실패를 앱 버그로 기록하지 않는다.

## 자동 테스트가 덮는 범위

`tests/`는 Node 내장 러너로 계약과 경합을 검증한다.

- `client.test.js`: 쿠키 전송, 경로 인코딩, 서버 필드 오류와 `Retry-After`, HTML 응답·시간 초과·
  취소 처리, SSE 이름 있는 이벤트와 명시적 종료
- `contracts.test.js`: Unicode 코드 포인트 한도, 추천 없는 후보 유지, 오래된 순위로 재정렬 금지,
  서버 ID 중복 제거와 순번 정렬
- `controller.test.js`: SSE `ready` 이후 보호 목록 조회, 추천 실패에도 후보 표시, 프로필 변경 시
  오래된 이유 무효화, 중단·재개 상태 보존, 늦게 도착한 응답이 다른 대화나 다른 참가자를
  덮어쓰지 않음, 전송 실패 시 같은 요청 ID 재시도, 종료 후 개인 상태 제거, 중복 입장 잠금,
  추천 재시도 쿨다운, 늦은 `/me` 응답이 완료된 참여 중단을 되돌리지 않음, 전송 응답이 아직 못 본
  상대 메시지를 건너뛰지 않음
- `mock.test.js`: 데모 입장 멱등성, 미입장·미등록 방 접근 거부, 프로필 버전 충돌, 대화 격리,
  이력 페이지네이션, 저장 실패의 명시적 오류

## 아직 검증하지 못한 것

프론트의 HTTP 호출부를 구현한 것과 실제 서버 통합을 끝낸 것은 다르다. `server/`의 제품 API가
아직 없어서 다음은 백엔드·AI와 함께 확인해야 한다.

- 두 실기기에서 서로 메시지를 주고받는 실제 왕복
- 서버가 발급하는 HttpOnly 쿠키의 수명과 Redis 재시작 후 세션 복원
- 서버 쪽 권한 검사와 전송 원자성, 멱등성 키 충돌의 실제 응답
- 실제 SSE 스트림에서의 재연결·누락 복원 동작(지금은 데모 어댑터로만 확인)
- 실제 AI 추천의 품질과 지연, 실패 시 사용자 안내
- 행사 종료 후 서버 쪽 정리와 종료 이벤트 전파

## 운영진 대시보드

`?view=dashboard`는 MVP 보류 범위다. 준비 중 안내만 제공하며 고정 숫자를 실시간 통계처럼
보여주지 않는다. 이 URL은 운영 권한이 아니므로 권한이 필요한 화면을 붙이기 전에 서버 인증이
먼저 있어야 한다.
