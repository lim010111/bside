# 검증 기록

마지막 실행: 2026-09-20 · 브랜치 `feat/frontend-ble-discovery`

테스트와 빌드가 통과했다는 사실만으로 제품이 동작한다고 적지 않는다. 아래는 실제로 실행해서
확인한 것과, 아직 확인하지 못한 것을 나눠 적은 기록이다.

## 실행한 명령과 결과

| 명령 | 결과 |
| --- | --- |
| `npm run lint` | oxlint 경고·오류 0건 |
| `npm test` | 40개 통과, 실패 0건 |
| `npm run build` | 성공. `mock.js`와 예시 참가자 데이터가 번들에 포함되지 않음 |
| `npm run build:demo` | 성공. `dist-demo/`에 `mock` 청크 포함 |

`npm run build` 출력에 `mock` 청크가 없다는 점이 "배포 빌드는 데모 데이터를 싣지 않는다"는
근거다. 이 두 빌드를 함께 돌려서 매번 비교한다.

## 브라우저에서 눌러본 것

개발 서버를 375×812 모바일 뷰포트에서 확인했다.

- 첫 실행: 닉네임·자기소개·만나고 싶은 사람 입력 후 시작 → `#nearby`로 이동, 주변 45명 표시
- 발견 패널: "주변 발견 켜짐"과 끄기 버튼이 보이고, 작동 안내에
  "이 화면에서는 주변 발견이 동작하지 않아요. Android 앱에서 확인해 주세요."가 함께 표시됨
  (브라우저에는 네이티브 플러그인이 없다. 이 문구가 나오는 것이 정상이고 정직한 상태다)
- 상세: 자기소개·만나고 싶은 사람·추천 이유가 표시되고, 이유가 상대의 원문을 인용함
- 채팅: 메시지 전송 후 말풍선 렌더링
- **발견 끄기**: 주변 목록 0명 + "주변 발견이 꺼져 있어요" 안내, 대화 목록은 유지되고
  상대에 "주변에 없음" 배지가 붙음
- **발견이 꺼진 상태에서 기존 대화**: 입력창이 열려 있고 전송 성공(말풍선 2개, 오류 없음)
- **발견이 꺼진 상태에서 새 상대**: 입력창 비활성화 +
  "주변 발견을 켜면 새 대화를 시작할 수 있어요.", 상세는 "지금은 주변에 없어요"
- 다시 켜기: 주변 45명 복귀
- 레이아웃: 375px와 320px 모두 `scrollWidth === clientWidth`로 가로 넘침 없음
- 콘솔 오류 0건

주의: 자동화 도구로 보낸 합성 클릭·키 입력은 일부가 대상 요소에 전달되지 않는다. 실제 이벤트가
요소에 도달하면 동작하므로, 자동화 실패를 앱 버그로 기록하지 않는다.

## 자동 테스트가 덮는 범위

`tests/`는 Node 내장 러너로 계약과 경합을 검증한다(40개).

- `client.test.js`: 설치 등록·프로필 수정의 경로와 페이로드, 공개 ID를 인증이 아닌 경로로만 사용,
  서버 필드 오류와 `Retry-After`, HTML 응답·시간 초과·취소, SSE 이름 있는 이벤트와 명시적 종료,
  `room.closed` 이벤트가 더 이상 구독되지 않음
- `contracts.test.js`: Unicode 코드 포인트 한도, 추천 없는 후보 유지, 오래된 순위로 재정렬 금지,
  관측 시각 기준 정렬, 양쪽 리비전이 바뀐 이유는 숨김, 선택적 보완 안내가 게이트가 아님,
  참여 의사와 라디오 상태의 분리
- `controller.test.js`: SSE `ready` 이후 보호 목록 조회, 추천 실패에도 후보 표시, 프로필 변경 시
  오래된 이유 무효화, 발견 ON/OFF 왕복, 늦게 도착한 응답이 다른 대화·다른 상대를 덮어쓰지 않음,
  전송 실패 시 같은 요청 ID 재시도, 이력 따라잡기, **발견 OFF 시 목록만 비고 기존 대화는 유지·전송
  가능**, **새 상대 첫 메시지는 거부**, **근접 이탈 시 기존 대화 접근 유지**, 중복 저장 잠금,
  추천 재시도 쿨다운, 늦은 `/me` 응답이 완료된 발견 변경을 되돌리지 않음, 전송 응답이 아직 못 본
  상대 메시지를 건너뛰지 않음, **발견 설정이 네이티브로 전달되고 실제 상태를 되읽음**,
  **라디오가 막혀도 참여 설정을 스스로 끄지 않음**
- `mock.test.js`: 데모 프로필 생성 멱등성, 재시작 후 발견 OFF 유지, 프로필·발견 리비전 충돌,
  첫 메시지의 근접·참여 검사와 기존 대화의 재검사 없음, 근접 이탈 후 대화 보존,
  발견 OFF 중 관측 보고 거부, 이력 페이지네이션, 저장 실패의 명시적 오류,
  추천이 0명으로 주저앉는 회귀 방지, 부정문("안 해봤어요")을 근거로 추천하지 않음

## 아직 검증하지 못한 것

프론트의 HTTP 호출부를 구현한 것과 실제 통합을 끝낸 것은 다르다. 다음은 다른 담당과 함께
확인해야 한다.

- **엔드포인트 경로 확정(T00).** `api/client.js`의 경로는 이 프론트의 제안이며 서버와 합의 전이다.
- **Capacitor `Discovery` 플러그인 구현(T01).** `lib/native.js`는 계약만 정의했고 Kotlin 구현이 없다.
  브라우저에서는 항상 `supported: false`로만 확인했다. 실제 권한 거부·Bluetooth OFF·배터리 제한
  상태에서의 화면은 실기기에서 다시 봐야 한다.
- 두 실기기에서 서로 메시지를 주고받는 실제 왕복
- 서버가 발급하는 설치 자격의 수명과 Redis 재시작 후 복원
- 서버 쪽 권한 검사와 전송 원자성, 멱등성 키 충돌의 실제 응답
- 실제 SSE 스트림에서의 재연결·누락 복원(지금은 데모 어댑터로만 확인)
- 실제 AI 추천의 품질·지연과 AI-D5의 "후보 20명·추천 갱신 5초" 목표
- 잠금 상태의 자동 추천 알림과 알림 탭 시 상세 이동
