# 검증 기록

마지막 실행: 2026-09-20 · 브랜치 `feat/frontend-ble-discovery` · [API 계약 v0.1](../docs/api-contract.md) 기준

테스트와 빌드가 통과했다는 사실만으로 제품이 동작한다고 적지 않는다. 아래는 실제로 실행해서
확인한 것과, 아직 확인하지 못한 것을 나눠 적은 기록이다.

## 실행한 명령과 결과

| 명령 | 결과 |
| --- | --- |
| `npm run lint` | oxlint 경고·오류 0건 |
| `npm test` | 44개 통과, 실패 0건 |
| `npm run build` | 성공. 데모 어댑터와 예시 참가자 데이터가 번들에 포함되지 않음 |

`npm run build` 출력에 `demo` 청크가 없다는 점이 "배포 빌드는 데모 데이터를 싣지 않는다"는
근거다. 이 두 빌드를 함께 돌려서 매번 비교한다.

## 브라우저에서 눌러본 것

개발 서버를 375×812 모바일 뷰포트에서, 저장소를 비운 상태로 시작해 확인했다.

- 첫 실행: 설치 등록 → 소개 입력 → 저장 → `#nearby`. **발견은 꺼진 채로 시작**하고
  "주변 발견 켜기"가 주 동작으로 보인다(계약대로 신규 설치는 `discovery_enabled: false`).
- 발견 켜기: 데모 라디오가 스캔 → 관측 보고 → 45명 표시. 패널에
  "예시 데이터로 보여드리는 화면이에요. 실제 BLE 발견이 아니에요."가 함께 표시됨
- 추천: "AI 추천은 아직 준비 중이에요."로 표시됨(v0.1은 항상 `unavailable`)
- 상세 → 메시지 보내기 → 전송 성공(말풍선 1개)
- **발견 끄기**: 주변 0명 + "주변 발견이 꺼져 있어요", 대화 목록은 유지되고
  상대에 "주변에 없음" 배지가 붙음
- **발견이 꺼진 상태에서 기존 대화**: 입력창이 열려 있고 전송 성공(말풍선 2개, 오류 없음)
- **발견이 꺼진 상태에서 새 상대**: 입력창 비활성화 + "주변 발견을 켜면 새 대화를 시작할 수
  있어요.", 상세는 "지금은 주변에 없어요"
- **재실행 복원**: 새로고침 후 입력 화면으로 되돌아가지 않고 같은 설치 사용자로 복원.
  대화와 꺼둔 발견 상태가 그대로 유지됨
- 레이아웃: 375px와 320px 모두 `scrollWidth === clientWidth`로 가로 넘침 없음
- 콘솔 오류 0건

주의: 자동화 도구로 보낸 합성 클릭·키 입력은 일부가 대상 요소에 전달되지 않는다. 실제 이벤트가
요소에 도달하면 동작하므로, 자동화 실패를 앱 버그로 기록하지 않는다.

## 자동 테스트가 덮는 범위

`tests/`는 Node 내장 러너로 계약과 경합을 검증한다(44개).

- `client.test.js`: 설치 등록만 인증 없이 호출하고 나머지는 Bearer 자격 증명을 싣는 것,
  자격 증명이 없으면 요청 자체가 나가지 않는 것, 프로필 전체 교체와 발견 상태 POST,
  `after_seq` 전진 전용 이력과 경로 인코딩, `{error:{code,message,details.field}}`를 필드
  오류로 변환, 계약 오류 코드의 한국어 문구, HTML 응답·시간 초과·취소,
  그리고 **`getNearby`·`getPerson`·`subscribe`가 존재하지 않는 것**
- `contracts.test.js`: Unicode 한도, 관측 순 정렬과 미평가자 유지, `message_id` 중복 제거,
  서버가 준 권한 창 기준의 첫 메시지 가능 여부, `unavailable`을 근거 부족으로 오해하지 않는
  선택적 안내, 참여 의사와 라디오 상태의 분리
- `controller.test.js`: 설치 1회 등록과 복원, 프로필 없는 신규 설치의 첫 화면,
  **주변 목록이 조회가 아니라 네이티브 관측 보고로 도착하는 것**, 푸시된 관측의 즉시 반영,
  관측 캐시에서 읽는 상세와 이탈 처리, 프로필 전체 저장, 서버 필드 오류의 입력 연결,
  발견 OFF 시 목록만 비고 라디오를 멈추며 대화는 유지, 기존 대화의 전송 유지,
  사라진 상대에게 첫 메시지 실패, 같은 키 재시도로 메시지 1건만 저장, 늦은 전송이 다른 대화에
  섞이지 않음, 이력 따라잡기, **전송 응답이 아직 못 본 상대 메시지를 건너뛰지 않음**,
  부트 실패 화면, 401 시 세션 초기화, 중복 저장 잠금,
  **라디오가 막혀도 참여 설정을 스스로 끄지 않음**
- `mock.test.js`: 등록 재시도의 자격 증명 재발급과 10분 만료, 무자격 호출 거부,
  프로필 전체 교체와 no-op, 임시 ID 회전과 겹침 인정, 발견/프로필 선행 조건,
  관측이 잡음을 무시하되 배치를 실패시키지 않는 것, 발견 OFF와 관측 만료가 첫 메시지만 막는 것,
  멱등성 키 재생·충돌과 `client_message_id`가 공개 모양에 없는 것, 전진 전용 페이지네이션과
  비당사자 접근 거부, 저장 실패의 명시적 오류

## 아직 검증하지 못한 것

프론트의 HTTP 호출부를 구현한 것과 실제 통합을 끝낸 것은 다르다.

- **서버 구현 자체(T02~T04).** `server/`에는 아직 health 라우터만 있다. 위 검증은 전부
  계약을 흉내 낸 데모 서버 대상이며, 실제 FastAPI 응답과 맞춰본 적이 없다.
- **Capacitor `Discovery` 플러그인 구현(T01).** `lib/native.js`는 계약만 정의했고 Kotlin
  구현이 없다. 실제 권한 거부·Bluetooth OFF·배터리 제한 상태의 화면은 실기기에서 다시 봐야 한다.
- 자격 증명을 Android 보호 저장소에서 WebView로 전달하는 실제 경로. 브라우저 폴백은
  `localStorage`이며 보호된 저장소가 아니다.
- 두 실기기에서 서로 메시지를 주고받는 실제 왕복과 BLE 임시 ID 회전의 실제 동작
- 서버 쪽 권한 검사와 전송 원자성, 10분 관측 권한 창의 실제 경계
- AI 추천 품질·지연과 AI-D5의 "후보 20명·추천 갱신 5초" 목표. v0.1에는 추천 자체가 없다.
- 잠금 상태의 자동 추천 알림과 알림 탭 시 상세 이동
