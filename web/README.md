# Bside — 프론트엔드

React + Vite. `spec/frontend-plan.md`의 0~6단계 완성본 — 셋업부터 운영진 대시보드까지.
7단계(실시간 폴링)부터는 아직 없다.

`http://localhost:5173/?view=dashboard` — 운영진 대시보드 (로그인 없이 URL로만 구분)

## 실행

```bash
npm install
npm run dev
```

`?r=KOSS26`(기본값) 또는 `?r=FEMEETUP`으로 방을 바꿔 열 수 있다.
`.env`에 `VITE_USE_MOCK=0`을 두면 `src/api/client.js`(아직 미구현)로 넘어간다 — 8단계 전까진 건드리지 않는다.

## 뭐가 됐는지

**입장 → 방 → 접점 시트, 전체 경로가 실제로 동작한다.** 목 데이터 기준.

- 방 45명(코쓱톤) / 22명(밋업), 소속 필드가 행사마다 다르게 렌더된다
- 입력 검증 4종(닉네임/소속/상태/한 줄), 수정 모드(닉네임·소속도 다시 받는다)
- 방 목록: 닿는 거리/조금 떨어진 곳 분리, 시간순 정렬, 만료 실선 + 페이드, 방 구성 띠
- 접점 매칭(1.5초 지연 후 시트 자동 오픈), 근거 도표, 강도 막대, 첫마디 인용
- 만료는 **실제 5분 TTL로 라이브 확인함** — 디버깅하다 방 인원이 45→17로 주는 걸 보고
  처음엔 버그인 줄 알았는데, 실제로 그만큼 시간이 흘렀던 것이었다. 의도대로 작동한다.

## 프로토타입과 다른 점 (의도적인 것)

### 1. "내 상태" 섹션 + "접점 N개" 재진입 행 — 사용자 레퍼런스 반영

프로토타입은 매칭되면 시트가 자동으로 뜨고, 닫으면 다시 열 방법이 없었다.
사용자가 참고 이미지를 보내서 두 가지를 반영했다:

- `내 상태` 라벨 + `수정` 링크로 분리 (카드 배경 없이 실선 구분 — `.section` 클래스)
- `접점 1개 / OO님과 이야기해 보세요` 상시 행 (`TouchpointEntry.jsx`) — 시트를 닫아도
  다시 열 수 있다. 매칭은 방에 들어온 뒤 **한 번만** 조회하고(`matchChecked` 플래그),
  수정하고 돌아와도 다시 "찾는 중"이 뜨지 않는다.

### 2. 목록 카드는 클릭이 안 된다 — 의도적으로 뺐다

프로토타입은 아무 카드나 눌러도 `openSheet(p.id)`가 열렸는데, 실제로는 **항상 같은
고정된 텍스트**(민서·CI 얘기)가 떴다. 데모 단축키였지 실제 동작이 아니다. 실제로
포팅하면 세연(담배 피우러 나간다는 사람) 카드를 눌러도 "CI 구축 얘기"가 뜨는 오류가
된다. 그래서 카드는 정보 표시용으로만 두고, 접점 시트는 `TouchpointEntry`(AI가 찾은
그 한 명)로만 연다 — `PersonCard.jsx` 주석에 이유를 적어뒀다.

### 3. 미리보기 화면 없음

사용자 지시. `spec/frontend-plan.md`에도 이미 반영되어 있던 결정. 입장 화면이 곧
첫 화면이고, 올려야 방이 열린다.

## 버그 네 개, 실기기 테스트로 잡음

빌드하면서 브라우저에 실제로 채워 넣고 돌려보다가 나온 것들. 셋 다 코드만 보고는
안 보였다.

1. **`require()` 브라우저 크래시** — Entry.jsx 초안에서 상태 라벨 조회에
   Node 스타일 `require()`를 썼다. ESM 번들에선 없는 함수라 즉시 죽는다. import로 교체.
2. **소속이 화면엔 보이는데 실제 값은 비어있던 문제** — `room`이 비동기로 로드되기 전에
   `Entry`가 먼저 마운트되면서, 소속 `useState` 초기값이 빈 문자열로 굳었다(useState
   초기화는 최초 1회뿐이라 이후 room이 도착해도 안 바뀐다). `<select>`는 "국민대"를
   보여주지만 실제 값은 `''`라 "소속을 입력해 주세요" 에러가 났다. `App.jsx`가
   `room` 로드 전엔 아무것도 마운트하지 않도록 고쳤다.
3. **헤드카운트가 46명이어야 할 자리에 47명** — `getMembers()`가 "나를 제외한
   목록"이라고 스스로 적어놓은 계약을 어기고, `join()`/`updateStatus()`가 저장한
   내 기록까지 목록에 섞어 반환했다. `getMembers()`는 시드만 반환하도록 정리.
4. **수정해도 내 만료 시계가 안 늘어남** — 프로토타입의 `saveStatus()`는 수정 때도
   `S.t0 = Date.now()`를 다시 찍어 5분을 리셋한다("아직 여기 있다"는 신호). React판은
   `STATUS_UPDATED`에서 `t0`를 안 건드려서 4분에서 그대로 이어졌다. 리듀서에
   `t0: Date.now()` 추가.

## 구조

```
src/
  api/
    shapes.js    데이터 계약 문서 (JSDoc). 실제 코드는 없다
    mock.js      목 구현 — ROOMS/STATUSES/SEED_HACK/SEED_MEET 전부 프로토타입 이식
    client.js    진짜 백엔드 스텁. 8단계에서 채운다
    index.js     스위치. 화면 코드는 항상 여기만 import한다
  lib/
    expiry.js    ageOf/lifeOf/fadeOf — now를 인자로 받아서 카드 46장이 한 시계로 움직인다
    tally.js     집계 문구 + 구성 띠 계산
  state.jsx      useReducer + Context. 화면이 둘뿐이라 라이브러리 없이
  screens/
    Entry.jsx    입장 (+ 수정 모드 재사용)
    Room.jsx     방 목록 + 매칭 오케스트레이션
  components/
    PersonCard, Composition, MyStatusCard, TouchpointEntry, TouchpointSheet
```

CSS는 `src/index.css` — `prototype/index.html`의 `<style>`을 그대로 옮기고,
React 전용 추가분(섹션 라벨, 접점 재진입 행)은 파일 맨 아래 별도 구간에 있다.

## 5단계 — 채팅

접점 시트의 "말 걸기"가 이제 진짜로 채팅 화면을 연다. `lib/bleChat.js`가 메시지를
들고 있고 — **`api/`가 아니라 `lib/`인 이유는 실제 BLE 채팅은 서버를 거치지 않기
때문**이다(protocol.md 0번). 9단계에서 이 파일만 Capacitor BLE GATT 호출로
갈아끼우면 되고 `Chat.jsx`는 안 바뀐다.

방으로 돌아가면(`뒤로`) Room으로 정확히 복귀한다 — Entry로 안 새고, 접점 재진입
행도 그대로 남는다. 실기기로 보낸 메시지 → 자동 응답까지 확인함.

**자동화 도구 관련 메모** (앱 버그 아님): 이 브라우저 자동화 도구의 `key: Enter`
시뮬레이션이 이 입력창에서 React의 `onKeyDown`까지 안 닿는 경우가 있었다. 네이티브
`KeyboardEvent`를 직접 dispatch하면 정상 동작해서 코드는 맞다는 걸 확인했고,
실제 키보드·모바일에서는 문제 없을 것으로 본다. 전송 버튼은 항상 정상.

## 6단계 — 운영진 대시보드

**모바일로 만들었다.** 지금까지 전부 모바일 전용이라 PC 레이아웃을 따로 짜면
이 단계 예상 시간(30분)을 넘긴다는 게 첫 번째 이유고, 운영진도 행사 중엔 폰으로
확인할 가능성이 높다는 게 두 번째 이유다. PC가 필요한 "종료 후 PDF 리포트"는
실시간 화면이 아니라 별도 내보내기 기능(roadmap.md v0.2)이라 지금 범위가 아니다.

로그인은 안 만들었다 — `?view=dashboard` 쿼리로만 참가자 화면과 구분한다. 실제
배포에서는 이 링크를 운영진에게만 공유하는 방식이 된다. 숫자는 PRD F5가 명시적으로
허용한 대로 하드코딩(`api/mock.js`의 `getDashboard()`) — 진짜 집계는 7단계 이후.

## 아직 라이브로 못 본 것

- **방이 완전히 빔** / **접점 없음** 화면 — 로직은 프로토타입에서 검증된 걸 그대로
  옮겼고 코드 리뷰로는 맞는데, 실제로 트리거하려면 시드 45명이 전부 만료(5분)되거나
  방에 `CAN_SHARE`가 하나도 없어야 해서 이번 세션에서 라이브 클릭으로는 못 봤다.
- 밋업 방(`?r=FEMEETUP`)은 소속 렌더링만 확인했고 전체 흐름은 안 돌려봤다.
