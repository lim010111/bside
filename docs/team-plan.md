# 4인 팀 작업과 통합

2026-09-20. 팀은 4명이며 김성빈이 프론트를 맡는다. 나머지 실명·시연 기기·내부 마감은 확인되지 않았다. 팀에 개발이 익숙하지 않은 사람이 1명 있다는 기존 조건을 보존한다. 아래 역할은 제안이며 배정 완료가 아니다.

## 역할 제안

| 역할 | 책임 |
| --- | --- |
| 김성빈·프론트 | React 입력·목록·상세·바로 채팅·복원·상태 표현, 네이티브 브리지 연결 |
| Android 담당 | Capacitor·Kotlin·권한·광고·스캔·배경 보고·추천 알림·실기기 설치 |
| 서버·AI 통합 담당 | 설치 인증·프로필·관측·추천 모듈·대화 저장·배포, AI 결과 계약 |
| 검증·시연 담당 | V01~V12·E01~E08 입력/기대 결과·재현·증거·발표, 작고 분리된 보조 작업 |

BLE가 핵심이 되며 네이티브 책임을 별도로 둔다. 서버와 AI를 한 역할에 모으는 부담이 있으므로 AI 평가 사례·프롬프트 비교는 검증 담당과 함께 수행하고 UI 담당도 통합에 참여한다. 담당자가 평가 방식을 선택한다는 기존 위임은 유지한다. 경험이 적은 사람에게 네이티브 장애·배포·통합을 단독 배정하지 않는다.

## 작업 단위

| ID | 결과 | 선행·검증 |
| --- | --- | --- |
| T00 | 최신 문서·공동 입력/응답 예시·필드/구현 기본값 합의 | 제품 합의 완료, 담당/기기 확인 필요 |
| T01 | Android 설치·실제 광고/스캔·수명주기 | T00, V02/V10 |
| T02 | 설치 인증·입력 수정·동일 설치 복원 | T00, V01/V07 |
| T03 | 관측 보고·유효 후보·상세 | T01/T02, V03/V06 |
| T04 | 첫 메시지·직접 채팅·이력·중복 방지 | T02/T03, V04/V05/V06/V11/V12 |
| T05 | 양쪽 의도 추천·Promptfoo 비교·버전 | T02/T03, E01~E08/V08 |
| T06 | 배경 발견→서버 결과→추천 알림 | T01/T03/T05, V09/V10 |
| T07 | 실제 두 사용자 통합·재시작·오류 회귀 | T01~T06, V01~V12 |
| T08 | 배포 경계·영상·발표·제출 자료 | 검증 결과, 공식 제출 기준 |

이전 방별 API·요청/수락 UI·운영자 종료·시연 전용 삭제는 작업으로 배정하지 않는다. 기존 mock을 먼저 실제 관측·저장·두 사용자 메시지로 연결한다. 사용자에게 이미 위임받은 스캔/관측 수치·모델·프레임워크를 다시 선택받지 않는다. 새로운 제품 행동 변경만 결정 기록에 되돌린다.

현재 위 작업은 계획이며 구현·역할 배정·배포 완료를 뜻하지 않는다. [개발 기준](development-contract.md), [API](api-contract.md), [검증](validation.md)을 공통 원본으로 사용한다.
