# BLE MVP API와 데이터 계약

2026-09-20. 제품 행동은 [개발 기준](development-contract.md), 변경 이력은 [B1~B14](product-direction.md)를 따른다. 아래 필드·경계는 기술 위임에 따른 설계 계약이며 구현된 API가 아니다. 엔드포인트·제한 수치는 구현 시 공동 예시와 OpenAPI로 고정한다. 이전 방별 API와 쿠키 계약은 [이력](history/event-mvp/docs/api-contract.md)에 보존하며 사용하지 않는다.

## 식별과 인증

- 첫 실행에서 설치 단위 사용자를 등록하고 서버가 공개 사용자 ID와 추측 불가능한 인증 자격을 분리해 발급한다.
- 인증 자격은 Android에서 보관하고 재실행 시 재사용한다. JS 상태·닉네임·BLE 주소를 인증으로 사용하지 않는다. 다른 설치에서의 복원은 지원하지 않는다.
- BLE로 교환하는 임시 식별자는 서버가 사용자로 해석한다. 임시 식별자를 아는 것만으로 프로필 전체·대화·인증 자격에 접근하지 못한다.
- 앱 삭제·재설치는 새 설치 범위다. 기존 서버 데이터의 자동 삭제로 해석하지 않는다. Android 백업을 통한 자격 복원은 이 범위와 맞게 구성한다.

## 데이터 경계

| 객체 | 핵심 필드·의미 | 수명 |
| --- | --- | --- |
| 사용자 | `user_id`, 닉네임, `self_description`, `connection_intent`, `profile_revision` | 같은 설치로 복원 |
| 발견 참여 | `discovery_enabled`, 변경 버전 | 직접 OFF 전까지 참여 의사 유지 |
| 임시 식별자 | 불투명 토큰, 사용자 연결, 유효 기간 | 회전·만료, 공개 프로필과 분리 |
| 근접 관측 | 관측자·상대, 관측/수신 시각, 식별자 유효성 | 짧은 유효 기간, 대화 수명과 독립 |
| 추천 | 조회자·상대, 양쪽 입력 버전, 정책 버전, 상태·순서·이유 | 입력 변경·정책 변경에 맞춰 재평가 |
| 대화 | `conversation_id`, 두 사용자 ID, 첫 메시지 저장 시각 | 거리·발견 OFF와 독립 |
| 메시지 | `message_id`, 대화, 발신자, 클라이언트 중복 방지 키, 본문, 서버 순번·저장 시각 | 복원 가능하게 저장 |

`room_id`, 행사 종료, 요청 상태·수락 상태, `is_demo` 같은 시연 전용 분기를 새 모델에 넣지 않는다. 필드명은 구현 계약이며 사용자가 이름을 직접 정한 것은 아니다.

## API 기능 단위

| 기능 | 서버 검사·결과 |
| --- | --- |
| 설치 등록·본인 복원 | 본인 자격 발급/확인, 같은 사용자와 입력 복원 |
| 프로필 조회·수정 | 본인만 수정, 버전 증가, 관련 추천 무효화 |
| 발견 ON/OFF | 본인 의사 갱신, OFF 후 새 후보 노출·새 상대 대화 제한 |
| 관측 묶음 보고 | 인증된 관측자, 임시 식별자·시간·중복 검사, 권한 없는 사용자 정보 반환 금지 |
| 주변 목록·상세 | 양쪽 참여와 관측 유효성, 입력 완료 여부 검사; 낮은 추천 점수만으로 제외 금지 |
| 첫 메시지 | 기존 대화가 없으면 현재 발견·참여 조건 검사 후 대화와 첫 메시지를 함께 저장 |
| 기존 대화 전송 | 대화 당사자 인증; 근접성·발견 ON을 다시 필수로 요구하지 않음 |
| 대화/이력 조회 | 당사자만 접근, 커서 이후 순번으로 복원 |
| 추천 작업 결과 | 입력 버전·관측·참여 재확인, 알림 적합 여부와 중복 키 제공 |

대화 열기만으로 관계를 만들지 않는다. 첫 메시지 저장이 신규 관계의 시작이다. 동시에 양쪽이 첫 메시지를 보내도 사용자 쌍당 대화를 중복 생성하지 않는다. 같은 메시지 재시도는 원래 저장 결과를 반환한다.

관측은 서비스의 근접 신호이며 위조 불가능한 위치 증명이 아니다. 임시 식별자·시각·인증 검사 없이 임의의 사용자 ID 신고만으로 프로필 접근 권한을 부여하지 않는다. 더 강한 관측 증명은 별도 검증 과제다.

## 순서·실패·동시성

서버 저장 성공 후 전송 성공을 응답한다. 이벤트·알림 전달은 저장 자체를 대신하지 않으며, 유실 시 이력 조회로 복구한다. 앱이 같은 메시지를 재전송할 때 중복 키를 유지한다. 서버 순번을 정렬 기준으로 사용하며 휴대폰 시각을 권위로 삼지 않는다.

프로필 수정·OFF와 동시에 끝난 추천은 버전을 재확인한다. 기존 대화가 없을 때 OFF/근접 만료와 첫 메시지가 경합하면 저장 직전에 자격을 확인한다. Redis 원자 처리에는 외부 LLM 호출을 넣지 않는다. 데이터 타입·인자 검사를 쓰기 전에 수행한다.

인증 실패·입력 미완료·관측 만료·상대 발견 OFF·존재하지 않는 사용자·메시지 저장 실패·추천 대기/실패를 구분한다. 클라이언트는 실패한 전송을 성공한 말풍선으로 확정하지 않는다. 수락 대기 오류나 행사 종료 오류는 없다.

## AI 모듈 경계

입력은 서버가 허용한 후보 목록과 조회자/후보의 ID, 자기소개, 교류 의도, 각각의 입력 버전이다. 출력은 그 후보 ID에 대응하는 내부 정렬 평가·근거·평가 상태·사용한 입력 버전이다. 이유는 조회 방향에 따라 달라질 수 있다. 미평가·실패·정보 부족을 낮은 점수나 성공 추천과 동일시하지 않는다.

AI는 후보를 창작하거나 근접·참여·대화 권한을 바꾸지 않는다. 낮은 평가·실패라도 유효한 사용자는 목록에 남고 직접 채팅할 수 있다. 숫자 점수는 화면에 노출하지 않는다. Promptfoo와 E01~E08 평가는 [AI 지침](../spec/prompts.md)을 따른다.

BLE 재관측마다 LLM을 호출하지 않는다. 양쪽 사용자·입력 버전·평가 정책 버전·조회 방향에 맞는 유효 결과를 재사용하며, 임시 BLE ID 회전을 새 사람으로 평가하지 않는다. 알림 전 조건 재검사는 캐시 적중 여부와 무관하다.

## 구현 기본값 관리

관측 유예·보고 간격·요청 timeout·본문 길이·재시도·알림 억제 값은 구성으로 관리하고 최초 실기기·AI 연결에서 값을 기록한다. 사용자 확정 또는 이미 달성한 성능으로 표기하지 않는다. 이 문서에 미정 수치를 임의 확정하여 팀별로 서로 다른 상수를 만들지 않는다. 구현 착수 시 서버·Android·UI 공동 예시와 값 목록을 한곳에 고정한다.

시연 데이터도 일반 데이터와 동일한 경로·보관 정책을 사용한다. 관측/캐시 만료와 사용자/대화 삭제를 구분한다.
