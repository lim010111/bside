# BLE MVP 검증과 증거

2026-09-20. 아래는 수행할 검증이며 실행 결과가 아니다. [개발 기준](development-contract.md)과 [API 계약](api-contract.md)을 따른다. 이전 행사 검증은 [이력](history/event-mvp/docs/validation.md)에 보존한다. 같은 ID를 볼 때 이 문서의 BLE 버전을 기준으로 한다.

## 기능 검증

| ID | 확인할 행동 | 통과 증거 |
| --- | --- | --- |
| V01 | 설치 등록·닉네임/소개/의도 입력 | 실제 Android 설치 사용자 생성, 입력 전 다른 사람 개인 정보 제한 |
| V02 | 실제 광고·스캔·신원 연결 | Android 두 대가 실제 상대를 발견. 하드코딩 BLE 상태 사용 금지 |
| V03 | 주변 목록·상세 | 유효 후보 전체와 정렬·두 원문·조회자별 추천 이유. 숫자 점수 미노출 |
| V04 | 별도 수락 없는 첫 메시지 | 유효 근접/참여에서 메시지 저장·상대 수신. 요청함·수락 상태 없음 |
| V05 | 실제 답장·중복 방지 | 두 사람이 실제 입력한 양방향 메시지와 재시도 시 중복 없음 |
| V06 | 이탈·발견 OFF | 기존 대화 조회·송수신 유지, 대화가 없는 새 상대와의 시작은 제한 |
| V07 | 앱 종료·재실행 복원 | 같은 설치 사용자·입력·대화·부재 중 메시지 복원 |
| V08 | 입력 수정·평가 버전 | 소개/의도 변경 후 오래된 이유·알림 노출 방지 |
| V09 | 백그라운드 자동 추천 알림 | 홈/잠금 상태 발견→서버 평가→시스템 알림→상세 진입. 실패 조건도 기록 |
| V10 | 실패 처리 | Bluetooth OFF·권한 거부·네트워크 단절·AI 실패·저장 실패를 구분, 거짓 성공 없음 |
| V11 | 권한·동시성 | 제3자의 대화 접근 불가, 동시에 첫 메시지를 보내도 쌍당 대화 하나, OFF와 신규 전송 경합 검사 |
| V12 | 영속 저장·동일 정책 | 서버 재시작 후 저장 확인, 시연/일반 데이터에 같은 계약, 행사·시연 종료로 특별 삭제 없음 |

실제 기기 모델·OS·앱 빌드·서버 버전·네트워크·실행 시각·조작·관측 결과를 기록한다. 성공한 조건과 실패한 조건을 분리한다. 새 상대와의 시작 제한 검증에는 기존 대화가 없는 사용자 쌍을 사용한다.

B12는 일단 포함하고 실제 문제가 생기면 재검토한다. 실패 시 로그와 재현 조건·원인·대안을 남기며 미완료를 성공으로 표시하지 않는다. 장시간 배터리 시험·하루 소모 목표는 사용자 지시에 따라 이번 선결 조건에서 제외한다.

## AI 사례 E01~E08

| ID | 사례 | 확인할 것 |
| --- | --- | --- |
| E01 | 같은 자기소개, 의도 A: 배포 문제 해결 | 사람이 기대한 추천 우선순위·근거를 기준으로 단순 규칙과 LLM 비교 |
| E02 | E01과 같은 소개, 의도 B: 함께 사이드프로젝트할 동료 찾기 | 단순한 순위 변화가 아니라 사람이 기대한 상대·근거로 바뀌는지 비교 |
| E03 | 유사성과 상보성 | 동일 태그뿐 아니라 도움 요청/제공 등 연결도 해석 |
| E04 | 양쪽 의도 불일치 | 우선순위에 반영하되 후보 삭제 금지. 복잡한 가중치 공식 선결하지 않음 |
| E05 | 정보 부족·모호한 입력 | 추천 근거 부족을 부적합·오류와 구분. 선택적 입력 보완 안내, 추가 입력 강제 없이 목록·채팅 유지 |
| E06 | 입력 안의 지시문 | 사용자 입력을 데이터로 처리, 후보·출력 규칙 유지 |
| E07 | 입력 수정·오래된 평가 | 입력 버전 검사·캐시 갱신 |
| E08 | 오류·시간 초과 | 추천 실패를 성공으로 꾸미지 않음, 목록·바로 채팅 유지 |

Promptfoo는 사용자 선택이며 아직 설치·실행한 것으로 기록하지 않는다. 사람의 기대 결과·단순 기준선·모델 결과·지연·호출/토큰 비용을 함께 남긴다. 모델 점수를 정확성이나 실제 만남 성과로 해석하지 않는다.

2026-09-20 [AI-D1~D5](planning.md#ai-개발-전-구체화-2026-09-20)를 다음과 같이 검증한다.

- 같은 입력·후보로 단순 결정론적 기준선과 복수 LLM 모델을 비교한다. 모델 결과를 보기 전에 사람이 기대하는 우선순위와 원문 근거를 기록하고, 프롬프트 조정에 쓰지 않은 사례로도 확인한다. 기존 mock을 기준선으로 사용할 경우 실제로 비교한 정렬·이유 생성 범위를 명시한다. 개선하지 못한 사례도 남긴다.
- 추천 이유는 1~2문장에서 구체적인 연결점과 근거를 전달하는지, 긴 한국어 입력에서도 실제 화면의 가독성이 유지되는지 확인한다. 필요한 한계 표현을 생략하거나 근거 없는 사실을 추가하지 않는다.
- 자동 알림은 초기의 신중한 기준에서 시작해 적합성 하이퍼파라미터별 오탐·누락·중복을 비교한다. 실험마다 모델·설정·정책 버전을 남기고 목록의 전체 후보 유지도 확인한다.
- 주변 후보 20명에서 목록 즉시 표시·추천 갱신 5초 이내를 초기 성능 목표로 측정한다. 측정 구간·반복 횟수·캐시 사용 여부·모델·프롬프트·사용량을 기록하고, 게이트웨이의 실제 과금 정보와 추정 비용을 구분한다. 목표는 후속 최적화 대상이며 보장 수치·고정 timeout이 아니다. 목표 초과나 AI 실패에도 목록·채팅을 사용할 수 있어야 한다.

위 검증은 계획이다. 아직 기준선 대비 LLM 우위, 특정 모델의 품질, 5초 목표 달성 또는 알림 임계값이 검증된 것으로 발표하지 않는다.
