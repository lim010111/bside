# 이번 MVP의 핵심 발견 흐름을 BLE로 전환한다

사용자는 행사 방과 QR이 미리 준비되지 않은 장소에서도 주변 사람과 교류하는 방향을 선택했고, 이번 MVP부터 BLE를 핵심 흐름으로 가져가기로 결정했다(B1). 인터넷 연결은 필요하다고 결정했다(B3). 기존 행사 전용·QR 입장·방 전체 추천·BLE 제외 구성을 새 MVP의 보편적 발견 모델로 적용하지 않는다.

## 대안과 결과

- **기존 행사 QR MVP 완료 후 BLE 확장:** 설치·배포 부담은 낮지만 이번 제출에서 장소 사전 준비 없이 주변을 발견하는 핵심 가치를 검증하지 못하므로 선택하지 않았다.
- **BLE 핵심 발견 + 인터넷 필요:** 사용자 선택. 행사도 사용 장면이 될 수 있지만 제품을 행사에 한정하지 않는다. 네이티브 기능과 실제 기기 검증이 필요하며 기존 웹·방 소속 계약의 재검토가 따른다.
- **BLE 기반 완전 오프라인·무서버:** 인터넷 필요 결정에 따라 필수 요구로 채택하지 않는다.

이 결정은 24시간 백그라운드 동작 보장, 모든 OS 지원, BLE 직접 채팅, 기존 Android/GATT 설계 재채택을 뜻하지 않는다. 발견 허용 시간(B2), 후보·공개·연락·수명 정책과 플랫폼은 [진행 중인 결정 기록](../product-direction.md)에서 후속 확정한다. 기존 자기소개·교류 의도 분리, 양쪽 의도를 고려하는 추천, Promptfoo 선택은 이번 전환만으로 철회하지 않는다.

후속 결정: [ADR-0002](0002-android-dwell-mvp.md)에서 Android 사용자 간, 몇 분 이상 함께 머무는 상대부터 검증하기로 했다. B2와 상세 구현 구성은 계속 미정이다.

후속 B2·B6·B7 결정: 발견 참여는 직접 끌 때까지 유지하고, 발견된 참여자 전체를 추천 순서로 표시하며, 첫 메시지 요청 수락 후 대화한다. 배터리 최적화·장시간 성능 논의는 해커톤 이후로 미뤘다. [최신 결정 기록](../product-direction.md)과 [ADR-0003](0003-conversation-request.md)이 위의 당시 미정 표기보다 우선한다.

2026-09-20 B13/B14: 위의 요청·수락 관련 후속 기록은 다시 변경되었다. [ADR-0005](0005-direct-chat-uniform-data.md)에 따라 바로 채팅하며 시연 데이터에도 같은 정책을 적용한다.
