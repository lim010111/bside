# Android 사용자 간 머무는 동안의 발견부터 검증한다

사용자는 이번 BLE MVP에서 몇 분 이상 같은 공간에 머무는 상대를 중심으로 검증하고(B4), Android 사용자 간 검증부터 시작하기로 했다(B5). 저전력 발견의 지연·누락과 iOS 잠금 상태·광고 호환성 제약을 고려해, 짧은 스침의 포착과 iPhone·교차 OS 동시 지원을 이번 필수 성공 조건에서 제외한다.

## 대안과 결과

- **몇 초의 스침까지 포착:** 발견·서버 평가·알림의 지연과 누락 요구가 엄격해진다. 이번에는 몇 분 이상 함께 머무는 상대를 중심으로 제품 가치를 검증한다.
- **처음부터 iPhone·Android 모두 지원:** 잠금 상태의 발견과 서로 다른 광고 동작을 동시에 해결해야 한다. 이번에는 Android 간 동작을 검증하고 iPhone·교차 OS는 후속 검증 대상으로 둔다. 현재 개발 환경에 설치된 도구는 선택 이유가 아니다.

‘몇 분 이상’은 고정 체류 시간 필터나 정확한 발견 지연 수치를 승인한 것이 아니다. Android 선택은 특정 프레임워크·최소 버전·GATT 채팅 설계의 채택도 아니다. 직접 끌 때까지 발견을 허용하는 B2와 실제 배경 동작의 수용 기준은 [결정 기록](../product-direction.md)에서 후속 확정한다. 기술 근거와 검증 계획은 [지속 BLE 조사](../../research/tech/ble-always-on.md)에 있다.

후속 B2·B6·B7 결정: 발견 참여는 직접 끌 때까지 유지하고, 발견된 참여자 전체를 추천 순서로 표시하며, 첫 메시지 요청 수락 후 대화한다. 배터리 최적화·장시간 성능 논의는 해커톤 이후로 미뤘다. [최신 결정 기록](../product-direction.md)과 [ADR-0003](0003-conversation-request.md)이 위의 당시 미정 표기보다 우선한다.

2026-09-20 B13/B14: 위의 요청·수락 관련 후속 기록은 다시 변경되었다. [ADR-0005](0005-direct-chat-uniform-data.md)에 따라 바로 채팅하며 시연 데이터에도 같은 정책을 적용한다.
