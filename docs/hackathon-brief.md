## 제공 자원

AI 크레딧 안내에는 `ai.cs.kookmin.ac.kr`에서 회원가입·로그인 후 지갑의 충전코드를 사용하는 절차가 나온다. ‘통합 API 게이트웨이’ 화면과 ‘API 키’ 메뉴가 있어 API 기능을 제공하는 화면은 확인된다. 팀 계정의 실제 호출 권한·지원 모델·잔액은 이미지로 확인할 수 없다. AI 구현 방식이 정해지면 실제 사용 가능 자원을 확인해야 한다.

근거: [가입 안내](info/KakaoTalk_20260919_141152826_02.jpg), [충전 안내](info/KakaoTalk_20260919_141152826_03.jpg).

2026-09-20 공개 접속 확인: 사이트와 `/api/status`는 HTTP 200을 반환했고, 상태 응답의 시스템명은 `국민대학교 소프트웨어융합대학 AI`, 버전은 `v1.0.0-rc.25-ko.5`, 문서 링크는 `https://docs.newapi.pro`였다. New API 기반 게이트웨이인 점을 확인했다. 인증 없이 조회한 `/v1/models`와 `/api/pricing`은 HTTP 401을 반환했다. 가입 안내 이미지에는 `/v1/chat/completions` 호출 예시가 있지만, 팀 API 키의 모델 접근 권한·지원 옵션·가격·잔액·실제 생성 호출 성공은 확인하지 않았다. 제공 자원이라는 사실을 특정 API 사용 의무가 확인된 것으로 확대하지 않는다.

지정 강의실은 429호·445호이며, 445호는 18시 이후 사용할 수 있다. 이동할 때는 팀원에게 공유하도록 안내한다. 팀의 현장 검증도 이 사용 범위와 시간 안에서 계획한다. [시설 안내](info/KakaoTalk_20260919_141152826_11.jpg)

## 평가를 개발에 연결하는 제안

아래는 주최 측 규정이 아닌 기획 제안이다. 특정 기능을 만들면 점수를 보장받는다는 뜻이 아니다.

| 평가 요소 | MVP와 발표에서 확보할 증거 | 피해야 할 공백 |
| --- | --- | --- |
| 문제 해결력 30 | 한 사용 장면의 불편, 기존 해결 방식과의 차이, 실제 대화로 이어지는 흐름 | 범용적인 ‘주변 사람 찾기’만 있고 누가 왜 쓰는지 불분명함 |
| AI 활용 15 | 교류 과정에서 AI가 맡는 구체적 판단·변환과 전후 비교, 실패 시 처리 | 프로필 요약을 붙이는 것만으로 교류 개선이 입증됐다고 주장함 |
| MVP 완성도 25 | 두 실제 사용자 사이에서 시작부터 끝까지 동작하는 핵심 흐름 | 기능별 화면은 있지만 기기 간 연결과 후속 행동이 끊김 |
| 사업화 15 | 사용자·구매자 구분, 도입 경로, 지불 이유와 검증할 가설 | 운영진의 구매 의사나 시장 수요를 확인한 사실처럼 표현함 |
| 발표·질의응답 15 | 5분 안의 문제 설명·시연·기술 선택·사업 가설, 예상 질문 답변 | 별도 시연 시간이 있다고 가정하거나 미구현 기능을 구현처럼 설명함 |

문제 해결력과 MVP가 합계 55점이다. 핵심 교류 흐름을 먼저 완성하되, AI 15점도 별도 요구로 다룬다. 기능 개수보다 각 평가 항목을 뒷받침할 관찰과 실행 결과를 확보하는 방향을 제안한다.
