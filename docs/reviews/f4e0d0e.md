# 최신 main 명세·프로토타입 검토

검토일: 2026-09-19. 대상: [f4e0d0ee7b09121717606f0b5162df85161b7c65](https://github.com/lim010111/kosscchthon/commit/f4e0d0ee7b09121717606f0b5162df85161b7c65). 사용자 요청으로 `git fetch origin main` 후 고정된 커밋을 읽었다. 작업 브랜치에 병합하거나 원격 파일을 수정하지 않았다.

**판정: 행사·밋업의 첫 대화라는 방향과 화면 자산은 활용할 수 있다. 구현 범위·AI 대상·공개 정책·성과 정의가 달라 현재 문서 묶음을 그대로 팀의 공통 개발 계약으로 사용할 수는 없다.**

이번 사용자가 확정한 것은 MVP 사용처가 행사·밋업이라는 점과 BLE·무서버가 수단 후보라는 점이다. 팀원이 독립적으로 작성한 명세의 ‘확정’ 표기, Bside라는 서비스명, 스택·기능·담당 배정은 참고안으로 구분한다.

후속 결정: Q4에서 사용자가 제공하는 **교류 의도를 LLM이 해석**하는 방향을 정했고, Q5에서 **같은 행사 방 전체**를 추천 대상으로 정했다. 따라서 아래 검토에서 지적한 고정 `STUCK × EXPERIENCED` 필터와 물리적 근접 필수 가정은 이후 명세에서 수정할 대상이다. 아래 표는 검토한 커밋 당시의 사실을 보존하며, 최신 결정은 [기획 문서](../planning.md)에서 관리한다.

Q6 후속 결정: 사용자는 **입력 후 참가자별 정보 열람**을 선택했다. 기존 프로토타입의 입력 전 닉네임·소속·상태·한 줄 공개는 수정 대상으로 확정됐으며, 필수 입력 항목과 참여 후 공개 필드는 후속 설계에서 정한다.

Q11 후속 결정: 사용자는 **별도 수락 절차 없는 1:1 채팅**을 선택했다. 채팅 제외 명세는 현재 범위와 맞지 않으며, BLE 전송을 필수로 선택한 것은 아니다. 아래에서 권장했던 별도 제안·수락·대면 확인 흐름은 현재 요구로 사용하지 않는다. 첫 메시지·수신·답장·실제 대면의 측정은 계속 구분한다.

Q13~Q15 후속 결정: 사용자는 **브라우저 복원·부재 중 메시지 보관·행사 종료 후 이용 종료**를 선택했다. 하트비트 중단만으로 참가자를 삭제하거나 연결이 끊기면 메시지를 잃는 계약은 수정 대상이다. 위임된 기술 선택에 따라 웹·FastAPI·SQLite와 서버 채팅을 개발 기준으로 잡았다. [현재 개발 계약](../development-contract.md)을 따르며, 아래 표는 검토 당시의 사실을 보존한다.

## 이전 검토 이후 달라진 것

`d18f5e1` 이후 HTML 프로토타입, 화면 캡처, 디자인 문서와 행사별 소속 설정이 추가됐다. PRD·MASTER·prompts·roadmap·scenario·기존 시드 데이터는 이전 검토 대상과 같다. 과거 [상세 검토](d18f5e1.md)의 제품·계약 충돌은 여전히 남아 있다. 시장·법률 관련 외부 주장은 이번 검토에서 새로 검증하지 않았다.

현재는 상호작용 가능한 HTML 코드가 있으므로 과거의 ‘문서만 있고 앱 코드 없음’이라는 상태 설명을 최신 main 전체에 적용하지 않는다. 다만 서버·실제 AI·기기 간 BLE가 연결된 구현은 해당 트리에서 확인되지 않았다.

## 인터뷰와 개발 명세로 반영할 순서

1. 행사 안에서 지원할 교류 목적, 추천 대상 범위, 입장 전 공개 정책과 남은 팀 여건을 확인한다.
2. 추천 이후 제안·응답·현장 식별·대면 확인을 결정한다. 그 흐름을 충족하는 전송 방식을 선택한다.
3. 공통 용어·상태 전이·데이터 예시·오류 응답·화면 완료 조건을 맞춘다. 팀의 각 작업이 동일한 예시와 계약을 사용하게 한다.
4. 기존 명세에서 채택·수정·보류할 부분을 표시하고 최종 개발 기준을 한 곳으로 모은다. 이번 검토 기록 자체를 새로운 확정 명세로 취급하지 않는다.

검증 범위는 고정 커밋의 정적 코드·문서 대조다. 프로토타입 실행, 실제 AI 호출, 서버 배포, 두 기기 통신·대면 교류 관찰은 수행하지 않았다.
