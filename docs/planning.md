# 제품 결정 안내

2026-09-20 현재 제품 결정의 원본은 [BLE 전환 기록 B1~B14](product-direction.md)이며 구현 행동은 [개발 기준](development-contract.md)을 따른다. 행사 MVP의 Q1~Q20과 당시 개발 인계는 [이력 문서](history/event-mvp/docs/planning.md)에 보존한다. 아래 AI 후속 결정은 새 방향과 충돌하지 않으므로 유지한다.

현재는 Android BLE 발견·인터넷 서버·지속 ON·발견된 전체 목록·바로 채팅·기존 대화 유지·같은 설치 복원·자동 추천 알림·시연 데이터 동일 취급을 채택했다. 별도 요청·수락 모델은 B13으로 폐기했다. 구현 코드는 아직 mock/기반 단계이며 문서 합의와 실제 동작을 구분한다.

## AI 활용·프롬프트 관리 후속 논의 (2026-09-19)

이 논의는 AI 활용 범위와 프롬프트 관리에 대한 후속 설계이며 구현 착수를 뜻하지 않는다.

- **AI-Q1 사용자 결정:** 추천에는 양쪽 교류 의도를 함께 고려한다(compromise). 의도 충돌 같은 세부 시나리오에 과도하게 집중하거나 복잡한 가중치 설계를 제품 논의의 선결 조건으로 두지 않는다. 특정 평균·최솟값 공식이나 대칭 점수를 확정한 것은 아니다. 기존 Q9와 공통 용어의 추천 점수 정의를 유지한다.
- **AI-Q2 사용자 의견:** 입력 구체화·첫마디·번역·대화 요약·운영진 요약은 핵심 기능으로 느껴지지 않는다. 이 후보들의 채택은 없으며, 핵심 교류 경험에 LLM을 더 잘 활용할 방식을 계속 검토한다.
- **AI-Q3 사용자 결정:** 프롬프트 평가 도구는 Promptfoo를 선택한다. 설치·평가 실행은 아직 하지 않았다. 원격 프롬프트 배포나 운영 추적 서비스의 추가 채택을 뜻하지 않는다. 프롬프트 지침과 평가 경계는 [AI 추천 구현 지침](../spec/prompts.md)에 기록한다.

다음 논의는 추가 AI 기능의 개수보다 사용자의 의도를 추천에 반영하는 핵심 경험을 다룬다. 아직 합의되지 않은 기능은 개발 범위나 용어집에 확정 사항으로 추가하지 않는다.

## AI 개발 전 구체화 (2026-09-20)

사용자가 여섯 질문에 답해 아래 방향을 정했다. 기존 AI-Q1~Q3와 BLE 제품 결정을 유지하며, 이 기록은 구현·평가 완료를 뜻하지 않는다.

- **AI-D1 — LLM의 개선 입증:** 단순 결정론적 추천보다 LLM 추천이 좋아야 한다. 같은 자기소개에서 교류 의도를 바꿀 때 순서가 달라지는 것만으로 성공으로 보지 않고, 사람이 기대한 상대의 우선순위와 원문에 근거한 이유를 함께 비교한다. ‘배포 문제 해결’과 ‘함께 사이드프로젝트할 동료 찾기’를 초기 비교 사례로 사용한다. 실제 우위는 평가 결과로 입증한다.
- **AI-D2 — 선택적인 입력 보완:** 모호한 입력은 ‘추천 근거 부족’으로 구분하고 목록과 채팅 이용을 유지한다. 구체적인 교류 의도를 더 적도록 자연스럽게 유도하되 추가 입력을 강제하거나 이용 조건으로 삼지 않는다. 낮은 적합성·추천 오류와 구분한다.
- **AI-D3 — 짧고 구체적인 추천 이유:** 연결점과 원문 근거를 1~2문장으로 설명한다. 프론트 가독성을 우선해 상세 화면에 간결하게 배치하고, 모든 설명을 목록에 펼치지 않는다. 불확실성이나 중요한 한계가 있으면 짧게 함께 전달한다. 고정 글자 수·펼침 방식은 프론트 구현에서 정한다.
- **AI-D4 — 조절 가능한 알림 기준:** 초기에는 알림을 신중하게 보내는 방향을 채택한다. 알림 적합성 기준은 조절 가능한 하이퍼파라미터로 관리하며 실험·사용 관찰에 따라 조정한다. 고정 점수 임계값을 확정하지 않았고, 전체 후보를 표시하는 목록 정책과 구분한다.
- **AI-D5 — 초기 성능 목표와 복수 모델 비교:** 주변 후보 20명에서 목록을 즉시 표시하고 추천 갱신 5초 이내를 초기 목표로 삼는다. 성능 보장·고정 제한이 아니며 지연·비용·품질은 후속 최적화 대상으로 다룬다. 여러 사용 가능한 모델을 같은 사례로 비교하고, AI가 늦거나 실패해도 목록 탐색과 채팅은 유지한다.
- **AI-D6 — 프롬프트 관리 담당:** 사용자가 직접 결정·관리한다. 기존 Promptfoo 선택은 유지한다. 제안했던 파일·Git 관리 방식이나 Langfuse 추가 도입을 사용자 확정 결정으로 기록하지 않는다.

AI 지침은 [spec/prompts.md](../spec/prompts.md), 평가 절차는 [검증 계획](validation.md), 사용자 표현은 [화면 명세](../spec/design.md)에 반영한다. 해커톤 게이트웨이의 확인된 사항과 인증이 필요한 모델·가격 정보는 [해커톤 기준](hackathon-brief.md#제공-자원)을 따른다. 구체 모델·호출 방식·캐시·임계값은 기존 기술 위임과 위 목표 안에서 실험으로 정하며 추가 제품 질문의 선결 조건으로 만들지 않는다.
