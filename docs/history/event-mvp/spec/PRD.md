# MVP 제품 요구

> **2026-09-19 제품 방향 전환:** 본문은 이전 행사 MVP의 명세·계획 또는 구현 자료입니다. 새 제품 방향은 BLE 기반 주변 교류이며, 이번 구현 범위와 대체 계약은 인터뷰 중입니다. 아래의 ‘현재·확정·개발 기준’ 표기를 새 방향의 승인된 요구사항으로 사용하지 않습니다. 현재 결정과 문서 전환 상태는 [BLE 근접 교류 전환](../../../product-direction.md)을 먼저 확인합니다.

현재 요구의 원본은 [Q1~Q20 결정 기록](../../../planning.md), 개발 시 기준은 [MVP 개발 기준](../../../development-contract.md)이다. 이 파일은 팀원이 기존 PRD 경로로 들어왔을 때 읽는 요약이다.

## 문제와 가설

행사·밋업에서 누구와 어떤 이야기를 시작할지 고르는 부담을 줄인다. 참가자가 자기소개와 지금 만나고 싶은 사람을 자유롭게 적으면 AI가 양쪽 맥락을 고려해 추천 순서를 정한다. 실제 적합성·대화 증가·도입 수요는 아직 검증할 가설이다.

## 필수 사용자 흐름

1. QR·링크로 계정 없이 들어와 닉네임·자기소개·만나고 싶은 사람을 입력한다. 입력 전에는 개인별 정보에 접근하지 못한다.
2. 같은 행사 방 참가자 전체를 추천 순서로 탐색한다. 의도가 맞지 않는 사람도 목록에 남으며 상세를 열 수 있다.
3. 배너를 눌러 자기소개·찾는 사람·나를 위한 추천 이유를 확인한다. 숫자 점수는 보여주지 않는다.
4. 별도 수락 절차 없이 1:1 텍스트를 보낸다. 상대가 답장할지 결정한다.
5. 앱을 닫았다 열어도 행사 종료까지 입력·대화를 복원한다. 부재 중 메시지도 저장한다.
6. 입력 수정과 참여 중단·재개를 지원한다. 중단 중 새 송수신은 거부하고 기존 이력은 열람한다. 재개하면 같은 참가자·대화를 사용한다.
7. 운영자가 행사를 수동 종료하면 목록·채팅 접근을 막고 종료 화면을 보여준다. 실제 삭제는 별도 정리 계약을 따른다.

## 구현과 평가

React/Vite/JavaScript, FastAPI, Redis 영속 저장, REST 전송·조회와 SSE 갱신을 사용한다. 현재 mock·서버 기반과 남은 작업은 [main 비교](../../../reviews/baea751.md)에 기록했다.

범위 밖: BLE 필수 연결, 위치·근접 판정, 역할 프리셋 강제, 사진, 별도 대화 수락 절차, 운영진 대시보드. 파일·읽음·푸시 등 부가 기능도 지금의 선행 조건으로 두지 않는다.

참가자는 사용자이고 행사 운영진은 도입 고객 후보다. 같은 소개·다른 의도로 추천이 달라지는 사례와 실제 두 사용자의 답장을 시연한다. 평가 배점은 문제 해결력 30·AI 15·MVP 25·사업화 15·발표 15이며, 구체적인 증거와 완료 조건은 [검증 계획](../../../validation.md)을 따른다.
