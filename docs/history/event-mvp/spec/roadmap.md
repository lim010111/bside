> **이력 자료:** BLE 전환 전 문서와 전환 중 안내를 보존한 자료입니다. 본문의 현재·확정 표기는 현행 요구가 아닙니다. [최신 결정](../../../product-direction.md)을 따릅니다.

# 개발 순서

> **2026-09-19 제품 방향 전환:** 본문은 이전 행사 MVP의 명세·계획 또는 구현 자료입니다. 새 제품 방향은 BLE 기반 주변 교류이며, 이번 구현 범위와 대체 계약은 인터뷰 중입니다. 아래의 ‘현재·확정·개발 기준’ 표기를 새 방향의 승인된 요구사항으로 사용하지 않습니다. 현재 결정과 문서 전환 상태는 [BLE 근접 교류 전환](../../../product-direction.md)을 먼저 확인합니다.

담당·선행 조건·검증 ID의 원본은 [4인 팀 계획 T00~T08](../docs/team-plan.md)이다. 기존 3명 가정과 ‘자정까지 BLE 추가’ 계획은 현재 기준으로 사용하지 않는다. 김성빈은 프론트 확정이며 다른 세 사람의 역할은 팀이 배정한다.

1. **T00:** 이미 있는 React/JS·FastAPI·Redis를 실행하고 mock/API의 두 자유 입력·응답 예시·같은 출처 연결을 맞춘다. 새 scaffold나 TypeScript 전환을 먼저 하지 않는다.
2. **T01~T04:** 화면 수정, 행사·세션·참가자 저장, AI 모듈·평가, 사용 관찰·시연 준비를 담당 경계에 따라 병렬 진행한다.
3. **T05:** 두 브라우저의 실제 입장·목록·상세를 연결한다. 추천 예시를 실제 AI 결과로 부르지 않는다.
4. **T06:** 실제 채팅·답장·부재 중 보관·재시작 복원을 완성한다.
5. **T07:** 실제 추천·입력 수정·중단/재개·운영자 종료·정리를 통합한다.
6. **T08:** V01~V12 결과와 AI 비교·수요 근거를 정리하고 시연·백업 영상·PPT/PDF를 준비한다.

초기 목표는 실제 두 사람의 대화까지 한 흐름으로 연결하는 것이다. BLE·대시보드·파일·읽음·푸시를 필수 흐름보다 먼저 구현하지 않는다. 실제 참여 시간·기기·나머지 담당자는 아직 확정되지 않았으므로 임의의 실명·완료 시각을 배정하지 않는다.

공식 마감은 [해커톤 안내](../../../hackathon-brief.md)를 따른다. 원격 배포·제출의 완료 여부는 직접 확인한 결과로 기록한다.
