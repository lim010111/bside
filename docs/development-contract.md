# BLE MVP 개발 기준

상태: **2026-09-20, B1~B14 통합. 사용자 최종 합의 완료. BLE 전환 코드 구현·실기기 검증 전이다.** 제품 원본은 [결정 기록](product-direction.md), 공통 용어는 [CONTEXT](../CONTEXT.md)다. 제목과 본문의 기준은 기존 행사 계약과 요청·수락 초안보다 우선한다. 이전 행사 계약은 [이력](history/event-mvp/docs/development-contract.md)에 보관한다.

## 제품 행동

Android 앱에서 자기소개·교류 의도를 입력하고 발견 참여를 켜면 주변의 참여자를 발견한다. 몇 분 이상 같은 공간에 머무는 사람을 중심으로 검증한다. 유효한 참여자 전체를 추천 순서로 표시하고 상세에서 두 원문·조회자를 위한 추천 이유를 보여준다. 숫자 점수는 보류한다. 인터넷은 필요하다.

사용자는 별도 요청·수락 없이 첫 메시지를 보내 1:1 대화를 시작한다. 수신자가 답장·대화 지속 여부를 정한다. 요청함·수락 전 추가 메시지 제한·거절/재요청 상태를 만들지 않는다. 기존 B7/B9는 B13과 [ADR-0005](adr/0005-direct-chat-uniform-data.md)로 대체됐다.

## 상태와 권한

| 상황 | 주변 발견·새 상대에게 첫 메시지 | 이미 시작한 대화 |
| --- | --- | --- |
| 양쪽 참여 ON, 유효한 근접 관측 | 목록·상세·첫 메시지 가능 | 이력 조회·송수신 가능 |
| 상대의 근접 관측이 유효하지 않음 | 현재 주변 목록과 새 대화 대상에서 제외 | 이력 조회·송수신 유지 |
| 발견 참여 OFF | 새 발견과 새 상대와의 대화 시작 중단 | 이력 조회·송수신 유지 |
| 앱 일시 부재 | 참여 설정·실제 작동·관측 신선도로 판단 | 메시지 저장, 복귀 시 조회 |
| 행사 종료·시연 종료 | 서비스에 별도 종료 사건 없음 | 동일하게 유지 |

별도 차단·삭제 사유가 없는 상태를 설명한 표다. 기존 ‘발견 OFF와 상대별 연락 중단은 다르다’는 의미는 유지하되 B13에서 제안한 상호 차단·읽기 전용·차단 해제 제한을 승인된 사양으로 추가하지 않는다. 세부 제한 기능은 이번 핵심 개발의 선결 조건이 아니다.

지속 ON은 사용자의 발견 참여 의사를 유지하는 정책이다. 권한·Bluetooth·네트워크·OS 상태에 따른 실제 작동은 별도로 표시한다. 네트워크가 끊긴 기기의 OFF를 서버가 즉시 아는 것처럼 설명하지 않는다. 서버는 수신한 상태와 관측 유효성을 기준으로 새 대화 권한을 검사한다.

첫 메시지가 저장되면 대화가 시작된다. 이후 상대가 떠나거나 참여를 꺼도 수신자는 그 메시지를 나중에 확인하고 답장할 수 있다. 대화를 열기만 하거나 빈 대화 객체를 만들기만 해서 이탈 후 새 연락 권한을 확보하게 하지 않는다.

## 입력·복원·데이터

닉네임·자기소개·교류 의도를 입력하고 같은 설치의 사용자로 복원한다. 별도 회원가입·재설치 복구·다른 기기 로그인은 이번 범위에서 제외한다. 기존 입력 수정과 두 자유 입력 구분은 유지한다. 앱 일시 종료만으로 사람을 새로 만들거나 이력을 지우지 않는다.

시연 데이터와 일반 데이터에 같은 정책을 적용한다. 별도 시연 플래그·만료·종료 후 일괄 삭제를 만들지 않는다. 이번 MVP에서는 시간 경과만으로 사용자·대화·메시지를 자동 삭제하는 정책을 추가하지 않는 것을 개발 기본값으로 둔다. 이는 영구 보관 보장이나 장기 운영 정책의 확정이 아니다. 근접 관측·임시 식별자·캐시의 기술적 만료는 대화 삭제와 구분한다.

데이터 초기화·운영 삭제가 필요하면 대상과 목적이 명확한 별도 작업으로 다룬다. 앱 재설치에 따른 복원 미지원은 서버 데이터가 자동으로 삭제된다는 뜻이 아니다.

## 자동 추천 알림

B12에 따라 앱을 보지 않을 때도 적합한 새 상대를 추천하는 시스템 알림을 이번 MVP에 포함한다. 목록에는 유효한 전체 후보를 남기지만 모든 발견마다 알림을 보내지 않는다. 동일 의미 입력의 반복 발견에는 평가·알림을 중복 실행하지 않는다. 평가 임계값과 중복 억제 시간은 AI/기술 담당이 평가해 정하는 구현 기본값이며 사용자 확정 수치가 아니다.

알림 직전 현재 참여·관측·입력 버전을 확인하고 늦은 평가를 현재 추천으로 꾸미지 않는다. 권한 거부·전송 실패를 추천 실패나 대화 수락으로 해석하지 않는다. 실제 구현·시연에서 문제가 확인되면 실패 조건과 대안을 기록하여 B12 범위를 재검토한다. 구현 전 우려만으로 제외하지 않는다.

## 구현 구성과 책임

기술 선택 위임에 따라 React/Vite UI + Capacitor Android 셸 + Kotlin BLE 계층, FastAPI·Redis 영속 저장을 출발점으로 선택했다([구성 근거](android-design.md)). 현재 코드에는 네이티브 계층이나 제품 API가 구현되지 않았다.

BLE는 주변 발견과 최소 신원 연결에 사용한다. 서버는 사용자 식별·후보 범위·추천·새 대화 권한·메시지 저장을 담당한다. BLE 직접 채팅은 요구하지 않는다. 백그라운드 관측·서버 보고·알림을 React 타이머에 맡기지 않고 네이티브가 처리한다. 기술 기본값은 [API 계약](api-contract.md), [프로토콜](../spec/protocol.md), [저장 계약](../server/docs/redis.md)에 구분한다.

AI는 양쪽 자기소개·교류 의도를 해석하고 순서·이유를 제공한다. 낮은 평가나 미평가만으로 목록을 지우지 않는다. 모델·평가·캐시는 기존 위임대로 AI 담당이 선택하며 Promptfoo를 사용한다. 원문에 없는 경험·관심사·의사를 만들지 않고 AI 실패에도 일반 목록과 채팅은 동작한다.

## 제외·후속 범위

- 행사 방·QR 입장·운영자 종료·행사 대시보드, 요청·수락 모델.
- iPhone·교차 OS, 몇 초의 스침을 놓치지 않는 보장, 정확한 미터 거리 보장.
- 완전 오프라인·무서버·BLE 직접 채팅.
- 장시간 배터리 시험·최적화. 사용자 지시에 따라 해커톤 이후 논의.
- 사진·파일·읽음·부가 채팅 푸시의 세부 기능. 자동 추천 알림과 구분.
- 계정·기기 간 복원, 시연 전용 삭제, 장기 운영 보관·사용자별 삭제 화면.

## 검증과 인계

[검증 계획](validation.md)에 따라 실제 Android 두 대에서 발견 → 추천 → 첫 메시지 → 수신·답장 → 이탈/OFF 후 기존 대화 유지와 앱 재실행 복원을 확인한다. 잠금 상태의 자동 추천 알림도 확인하되 장시간 성능 시험은 선결하지 않는다.

코드·실기기 검증 결과가 나오기 전까지 mock 자동 답장·고정 추천·BLE 연결 상수를 실적으로 소개하지 않는다. 문서 합의와 구현 성공을 구분한다. 2026-09-20 사용자가 최종 흐름과 문서 정리 결과를 확인하여 제품 인터뷰를 마쳤다.
