# 발표 흐름 — BLE 주변 교류 MVP

2026-09-20. 시연 포함 5분 구성안이다. [해커톤 원본](../docs/hackathon-brief.md)을 따르며 실제 검증 성공 전에는 아래 흐름을 구현 완료 주장으로 사용하지 않는다. 이전 무저장·5분 소멸·QR 중심 원고는 [이력](../docs/history/event-mvp/pitch/script.md)에 보존한다.

## 0:00–0:45 문제

같은 공간에 있어도 누가 어떤 교류를 원하는지 알기 어렵다. 자기소개와 지금 만나고 싶은 상대를 표현하고, 가까이 있는 사람 중 대화를 시작할 상대를 찾게 한다.

## 0:45–1:20 제품

Android 앱에서 발견을 켜면 BLE로 주변 참여자를 찾고 서버가 양쪽 소개·의도를 바탕으로 추천한다. 사전 행사 방은 필요 없다. 인터넷과 앱 설치는 필요하다. 행사는 활용 장면 중 하나다.

## 1:20–3:30 시연

[두 사용자 시나리오](../spec/scenario.md)의 실제 성공한 흐름을 보여준다. 발견·의도 변화에 따른 추천·잠금 상태 추천 알림·바로 첫 메시지·실제 답장·발견 OFF 뒤 기존 대화 유지·재실행 복원을 우선한다. 요청·수락 버튼은 없다. 알림이 실패했다면 제한과 재검토 결과를 설명하고 모의 성공으로 대체하지 않는다.

## 3:30–4:20 기술과 AI

React/Capacitor 화면, Kotlin BLE·알림, FastAPI·Redis 저장 경계를 설명한다. BLE는 발견, 인터넷은 추천·채팅을 담당한다. 같은 상대의 반복 관측과 새 LLM 평가를 구분한다. Promptfoo 평가와 사람의 기대 결과는 실제 실행한 결과만 제시한다.

## 4:20–5:00 검증과 다음 단계

실제로 검증한 기기·조건·동작을 명시한다. 현재 Android·머무는 상대부터 시작하며 iPhone·짧은 스침·장시간 배터리 최적화는 후속이다. 일상에서 반복 사용할 가치와 밀도·수익모델은 후속 검증 과제로 제시한다. 시연 데이터도 일반 데이터와 같은 저장 정책을 사용한다.
