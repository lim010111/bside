## 이전 덱 사용법

`deck.html`을 크롬으로 열고 `F11`. **방향키·스페이스**로 넘기고, 화면 왼쪽 1/4을 클릭하면 뒤로 간다.

영상과 폰트가 네트워크를 타므로 **행사장에서는 PPTX로 발표하는 게 안전하다.** PPTX는 각 장이 이미지라 폰트가 깨질 일이 없다.

## 디자인 기준

`spec/design.md`의 나이트 테마는 **앱 화면** 기준이라 덱에는 쓰지 않는다. 발표는 9/20 13시,
조명이 켜진 강의실이다. 어두운 배경은 프로젝터에서 뭉갠다.

- 배경 60% 흰색, 본문 30% `#1F1F24`, 강조 10% 앰버 `#B45309`. 6:3:1
- 색은 세 가지를 넘지 않는다. 6장 대조에서만 상태 3색을 쓴다. 거기서는 색이 데이터다
- **16:9 고정.** 1280×720 프레임 하나를 화면에 맞춰 축소하고 바깥은 검게 칠한다.
  16:10 노트북에서는 위아래에 레터박스가 생긴다. PowerPoint와 같은 동작이다
- **제목은 항상 같은 자리.** 위에서 72px. 내용만 남은 공간에서 가운데 정렬한다
- 제품 화면을 글로 옮겨 적지 않는다. 4·6·8·9장은 `prototype/shots/`의 실제 캡처를 쓴다

### 문체 — 개조식, 단 조사는 살린다

명사로 끝내되(`~음`, `~점`, `~앱`) **조사와 연결어미까지 지우지는 않는다.**
조사를 전부 빼면 전보문이 된다. 한 번 그렇게 만들었다가 되돌렸다.

| 지나침 | 적당함 |
|---|---|
| `행사장 참가자 간 즉시 대화 연결` | `행사장에서 닿는 거리의 사람과 연결되는 앱` |
| `원인: 용기 부족이 아닌 대화 상대 불명확` | `용기가 부족해서가 아니라, 누구에게 말을 걸어야 할지 모르는 점이 원인` |
| `네트워킹 효과성 긍정 응답 주최자 비율` | `자기 행사의 네트워킹이 효과적이라고 답한 주최자 비율` |
| `GPS 미사용. 근접 판정 단말 내 처리` | `GPS 미사용. 근접 판정을 폰 안에서 끝내므로` |

기준: **소리 내어 읽어서 말이 되면 통과.** 명사만 이어붙여 읽히지 않으면 조사를 되살린다.

- 문장 끝은 명사나 `~음/~함/~점`. `~습니다`로 끝내지 않는다
- 짧은 라벨(`서버 미경유`, `구현 현황`, `핵심 지표`)은 조사 없이 둬도 된다
- 긴 설명은 조사를 살린다. 두 개 이상 명사를 이어붙이지 않는다
- **`A가 아니라 B` 대구를 쓰지 않는다.** 장마다 강조색 경구로 끝내지 않는다
- 줄표(—)를 쓰지 않는다. 가운뎃점(·)은 짧은 병렬(`조직·직무`)에만
- 백업 장의 질문(`qa-q`)만 예외. 심사위원이 실제로 말하는 문장이라 존댓말 그대로
- 화면은 개조식, 입으로 하는 말은 존댓말 대본(`spec/scenario.md`). 매체가 달라서 안 부딪힌다

**음슴체와 헷갈리지 말 것.** `~함/~음` 종결은 같지만 음슴체는 반말이고 게임 갤러리·카톡·
군대 무전에서 쓰는 축약체다. 나무위키가 "투박하다, 기계 같은 인상"이라고 정리한 그 어감이다.
개조식은 조사만 줄이고 격식은 유지한다.
[국립국어원 온라인가나다](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&qna_seq=320204)

## 다시 뽑기

`deck.html`을 고친 뒤:

```bash
cd pitch && bash build.sh
```

본편과 백업이 각각 PDF·PPTX로 한 번에 나온다. 크롬과 `python-pptx`가 필요하다.

갈라내는 기준은 `deck.html`의 `data-backup` 속성이다. 백업으로 보낼 장에 그 속성을 붙이면 된다.

빌드 전에 `check.py`가 태그 균형을 본다. 닫는 태그가 하나 어긋나면 요소가 슬라이드 밖으로
새어나가 `#stage`에 붙고, **모든 장에 겹쳐 찍힌다.** 화면에서는 작은 얼룩으로만 보여 놓치기 쉽다.
