# 시연 영상 촬영 시나리오

덱 5장에 들어갈 **50초** 영상. 실기기 두 대를 동시에 녹화해 나란히 붙인다.

기준은 [검증 기록](../web/VERIFICATION.md)의 T07이다. **광고 → 스캔 → 관측 보고 → 서버
조회 → 첫 메시지 → 답장**이 실제 무선과 실제 서버로 도는 것을 그대로 찍는다.

## 역할

| | 누가 |
|---|---|
| 녹화 시작·회수·합성 | Claude (`tools/record-demo.sh`) |
| 폰 조작 | 사람 두 명 |

**조작을 자동화하지 않는다.** BLE 발견에 걸리는 실제 지연이 화면에 남아야 하고, 그게 무선이
진짜로 돈다는 증거다. 좌표 자동 탭은 기기마다 깨지기도 한다.

## 준비

```bash
bash tools/record-demo.sh check     # 서버·빌드·권한·배터리
bash tools/record-demo.sh reset     # 초기화 + 권한 + 소개 주입
```

`reset`이 끝나면 두 대가 이 상태가 된다.

- 입장 화면, **소개가 이미 채워져 있음**
- 발견 꺼짐, 대화 없음, 주변 0명

소개를 CDP로 넣는 이유는 **한글을 `adb shell input text`로 못 넣기 때문**이고, 50초 예산에
한글 타이핑 두 번을 넣을 자리가 없기 때문이다. 타이핑 장면까지 찍고 싶으면 화면에서 지우고
직접 입력하되 영상은 그만큼 길어진다.

### 두 사람의 소개

의도적으로 **상보 관계**로 짰다. 한쪽이 막혀 있고 한쪽이 해봤다. 추천이 성립하는 조건이다.

| | 승제 (왼쪽) | 우현 (오른쪽) |
|---|---|---|
| 자기소개 | 동아리에서 안드로이드 앱을 만드는데 블루투스 쪽이 처음이라 스캔이 자꾸 끊겨요. | 작년에 BLE 광고랑 스캔을 직접 붙여봤어요. 안드로이드 12 권한 때문에 한참 헤맸습니다. |
| 만나고 싶은 사람 | BLE 붙여보신 분께 막힌 데를 여쭤보고 싶어요. | 블루투스 붙이다 막힌 분 있으면 편하게 물어봐 주세요. |

이 입력으로 실제 생성된 추천 이유다.

> 이 분은 BLE 광고와 스캔을 직접 구현해봤고 안드로이드 권한 문제까지 경험했으므로,
> 블루투스 스캔이 끊기는 문제를 해결하는 데 도움을 줄 수 있습니다.
> 양쪽 모두 BLE 구현 경험 공유를 원하고 있습니다.

## 컷 시트 (50초)

```bash
bash tools/record-demo.sh rec 50
```

엔터를 치면 **즉시** 두 대가 녹화를 시작한다. 미리 폰을 잡고 있다가 바로 움직인다.

| 초 | 승제 폰 (왼쪽) | 우현 폰 (오른쪽) | 화면에 보여야 할 것 |
|---|---|---|---|
| 0–4 | 가만히 | 가만히 | 입장 화면. 두 줄이 적혀 있음 |
| 4–7 | **시작하기** | **시작하기** | 계정 절차 없이 바로 주변 화면 |
| 7–10 | **켜기** | **켜기** | `주변 발견 켜짐` |
| 10–20 | 기다림 | 기다림 | **`지금 가까이 1`로 바뀌는 순간** |
| 20–24 | **우현 카드** 탭 | 가만히 | 상세 진입 |
| 24–28 | **정지** | 가만히 | **`왜 추천했나요?` 전문** |
| 28–36 | **메시지 보내기** → 입력 → 전송 | 가만히 | 내 말풍선 1개 |
| 36–42 | 가만히 | **대화 탭** → 승제 열기 | 받은 말풍선 |
| 42–50 | 대화 화면 유지 | **답장 입력 → 전송** | **양쪽에 말풍선 2개** |

### 반드시 지킬 것 셋

1. **10–20초 구간을 잘라내지 않는다.** 실제 발견 지연이다. 측정해보니 한쪽이 5초, 양방향이
   11초 걸렸다. 이 기다림이 "진짜 무선"의 증거다.
2. **24–28초는 완전히 멈춘다.** 추천 이유가 이 영상에서 가장 비싼 4초다. 스크롤하지 않는다.
3. **메시지는 짧게.** 한글 입력이 길면 예산을 다 먹는다.
   - 승제 → `스캔이 자꾸 끊기는데 좀 여쭤봐도 될까요?`
   - 우현 → `권한 설정부터 볼까요`

## 하지 말 것

- **알림이 뜨면 그 테이크는 버린다.** 방해금지를 켠다
- 손가락으로 화면 절반을 가리지 않는다. 화면 녹화라 손은 안 찍히지만, 터치 위치에 따라
  키보드가 올라와 아래가 가려진다
- 발견을 껐다 켰다 반복하지 않는다. 관측이 만료돼 목록이 비는 구간이 생긴다
- **안 된 것을 된 것처럼 찍지 않는다.** 백그라운드 발견과 화면 꺼짐 상태는 아직 검증 전이므로
  영상에도 넣지 않는다

## 다시 찍기

```bash
bash tools/record-demo.sh reset     # 다시 깨끗한 상태로
bash tools/record-demo.sh rec 50
```

테이크마다 `reset`을 돌린다. 대화가 남아 있으면 다음 테이크에서 이전 말풍선이 보인다.

## 합성

```bash
bash tools/record-demo.sh stack
```

`output/demo/demo.mp4`가 나온다. 왼쪽 승제, 오른쪽 우현, 각 폰 위에 이름 라벨이 붙는다.

**자막은 편집기에서 얹는다.** 발표 중에는 말을 하지 않고 영상만 틀기 때문에 화면이 스스로
설명해야 한다. 최소 네 줄이면 된다.

| 시점 | 자막 |
|---|---|
| 4초 | 계정 없이 두 줄만 적고 시작 |
| 10초 | BLE로 주변 참여자를 찾는 중 |
| 24초 | 추천 이유는 양쪽이 쓴 원문에서 나온다 |
| 36초 | 수락 절차 없이 바로 대화 |

## 촬영 뒤 정리

```bash
bash tools/record-demo.sh density reset
```

촬영용으로 맞춰둔 화면 밀도를 원래대로 돌린다. 두 대의 기본값이 각각 450, 480이다.
