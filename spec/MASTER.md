# 1. 서비스

## Bside

**Connect with who's beside you.**
행사장에서 **닿을 수 있는 거리에 있는 사람**과 연결되는 앱.

**이름의 두 겹**
- **Beside** — 옆에 있는 사람
- **B-side** — 음반의 뒷면. **행사의 A면이 발표라면 B면은 사람이다.** 그리고 기억에 남는 건 대개 B면이다

> 할 일: 앱스토어·구글플레이에서 "Bside" 검색 (음악 서비스 충돌 가능)

# 2. 목적과 문제

## 문제

밋업이나 컨퍼런스에 혼자 가본 사람은 안다. 네트워킹 시간 30분이 주어진다. 아는 사람끼리 뭉치고, 혼자 온 사람은 음료 테이블 옆에서 폰을 본다. 명함 몇 장은 받지만 왜 이 사람인지 모른다. 그리고 30분이 끝난다.

**말을 걸 용기가 없어서가 아니다. 누구에게 왜 걸어야 하는지를 모르기 때문이다.**

| 근거 | 출처 |
|---|---|
| 주최자의 **15%만** 자사 네트워킹이 매우 효과적이라 평가 | Converve 벤치마크 |
| 참가자 **30% 미팅 예약을 실패**로 봄. 대표 사례 TechBBQ 채택 58%·수락률 39% | Brella |
| 무료 대면 행사 **노쇼 40~60%** | Converve |

→ **돈 내고 전용 앱을 깔게 해도 절반이 안 쓴다. 무겁기 때문이다.**

## 목적

행사장에서 **낯선 사람에게 말을 거는 비용을 0에 가깝게** 만든다.
설치 없이 들어오고, 30초 만에 상태를 달고, **말 걸 이유와 첫마디**를 받고, 필요하면 **서버를 거치지 않고 직접 대화**한다.

# 3. 해결

```
주최자가 QR 띄움
   ↓ 3초
입장 (닉네임·소속만. 계정 없음)
   ↓ 30초
상태 한 줄 — "🔍 배포·CI 경험 있으신 분 찾아요"
   ↓
방 목록 + BLE로 잡힌 사람은 "닿는 거리" 표시
   ↓
AI가 상보 관계 발견 → 카드 + 첫마디
   ↓
BLE 채팅으로 "지금 갈게요"  ← 서버를 거치지 않는다
   ↓
만나서 이야기한다
   ↓
행사 끝 → 전부 소멸
```

## 핵심 개념 — 접점은 공통점이 아니라 상보성이다

| | 유사도 매칭 | Bside |
|---|---|---|
| 잇는 대상 | "배포에서 막힘" ↔ "배포가 처음이라 막막함" | "배포·CI 경험자 찾음" ↔ "작년에 도커 CI 구축해봄" |
| 겹치는 단어 | 많음 | **0개** |
| 결과 | 둘 다 모른다 ❌ | 찾는 사람과 해본 사람 ✅ |

> **우리가 찾는 건 닮은 사람이 아니라 서로를 채우는 사람입니다.**

## 두 번째 개념 — 닿을 수 있는 거리에서만 대화한다

BLE가 닿는 범위가 곧 대화 가능 범위다. **물리적으로 같은 공간에 있어야 말을 걸 수 있다.**
그리고 그 대화는 **서버를 거치지 않는다.** 기기와 기기가 직접 주고받는다.

> 메시지가 어디에도 저장되지 않습니다. 카카오톡도 못 하는 일입니다.

### QR과 BLE는 서로 다른 일을 한다

| | 하는 일 | 성립 조건 |
|---|---|---|
| **QR** | *어느 무리*인지 자른다 — 이 행사, 이 장소에 온 사람 | 행사가 있어야 함 |
| **BLE** | *얼마나 가까운지* 판단한다 | 행사 없이도 됨. 아무 데서나 |

QR만 있으면 행사가 없는 날은 아무것도 못 한다.
BLE만 있으면 누가 같은 행사에 온 사람인지 모른다. 그래서 둘 다 쓴다.

### 왜 GPS가 아니라 BLE인가

GPS로 근접을 판정하려면 **서버가 내 좌표를 받아야 한다.** 서버가 그 좌표로 "둘이 가깝네"를 계산한다.
BLE는 그 계산을 **폰 안에서** 끝낸다. 서버에 올라갈 좌표가 아예 생기지 않는다.

한 걸음 더: BLE로 잡은 ID를 서버에 물어보면 좌표는 몰라도 **누가 누구 옆에 있었는지**는 남는다.
그래서 **ID 해석도 기기 안에서** 한다. QR로 들어올 때 방 명단을 이미 받아놨으니 서버에 물을 일이 없다.

> "GPS를 쓰면 여러분 위치가 저희 서버로 옵니다.
> 블루투스는 그 계산을 폰 안에서 끝냅니다. 저희 서버에는 올라갈 좌표가 없습니다."

정밀도로 주장하지 말 것. "GPS가 더 정확한데요"에 진다. **주장은 프라이버시다.**

# 4. 이 해커톤에 적합한 이유

## 주제 '교류' 적합성

| 축 | 어떻게 충족하나 |
|---|---|
| **사람과 사람** | 낯선 사람에게 말을 거는 비용을 없앤다. 결과물이 "만나서 이야기했다"이다 |
| **기술과 기술** | 서버를 거치지 않고 **기기끼리 직접** 대화한다. BLE가 닿는 거리가 곧 교류의 거리다 |

그리고 **이 대회 자체가 무대다.** 90명이 개인 접수로 와서 현장에서 처음 만났다. 심사위원과 참가자 전원이 오늘 겪은 문제다.

## 심사 기준별 근거

### 아이디어 및 문제 해결력 (30점) — 문제 정의와 차별성

**문제 정의**: 누구나 겪었고 숫자 근거가 있다(위 표). 심사위원도 겪어봤다.

**차별성 세 겹**
1. **국내 공백** — 이벤터스·온오프믹스·페스타 중 **참가자 간 매칭을 하는 곳이 하나도 없다**
2. **해외와의 차이** — Brella·Swapcard·Grip은 **사전 계획형**이다. 행사 전에 앱 깔고 프로필 채우고 미팅 예약. 그래서 채택 58%·수락 39%. 우리는 **현장 즉흥형**. QR 3초, 결과는 예약이 아니라 "지금 저분에게 이렇게 말 걸어보세요"
3. **상보성 매칭** — 겹치는 단어가 0개인 두 사람을 잇는다

**선제 방어** — 근거리 소셜 무덤(Highlight·Sonar·Banjo) 연상은 심사위원이 꺼내기 전에 먼저 말한다.
> "그들이 죽은 이유는 두 개입니다. 밀도를 스스로 만들어야 했고, 지불자가 없었습니다.
> Zenly는 4천만 MAU로도 수익화를 못 해 닫혔습니다.
> 저희는 밀도가 이미 있는 공간에만 들어가고, 그 공간을 운영하는 사람이 고객입니다."
> (참고: "배터리 때문에 죽었다"는 1차 출처가 없다. 이걸 말하면 엄밀함으로 읽힌다)

### AI 기술 활용성 (15점) — AI 적절성 및 기술 이해도

**적절성** — "배포·CI 경험자 찾음"과 "작년에 도커 CI 구축해봄"은 겹치는 단어가 0개다.
키워드 매칭으로도, **임베딩 유사도로도 안 된다.** 유사도는 오히려 둘 다 막힌 사람을 이어준다.
**상보성은 유사도의 반대다.** 이 판단은 LLM만 한다.

**기술 이해도 — 말할 거리 다섯 개**
1. **AI에게 안 맡긴 것**: 방 필터, 만료 검사, 중복 차단, 강도 임계값, 집계 계산은 전부 코드
2. **호출 수 관리**: 20명이면 쌍이 190개. 코드로 후보를 좁혀 보통 5회 이하
3. **프롬프트 인젝션 방어**: 남의 자유 입력을 시스템 프롬프트에 넣지 않는다
4. **BLE 31바이트 제약**: 광고로는 한글 여섯 자. 그래서 GATT 연결로 간다
5. **위치정보법**: GPS·와이파이 AP를 쓰면 저장 안 해도 신고 의무. 우리는 안 쓴다.
   이건 규제 회피가 아니라 설계 선택의 결과다 — 근접 판정을 기기 안에서 끝내니 좌표가 생기지 않는다

### MVP 구현 및 완성도 (25점)

**가장 위험한 항목.** BLE 자유 채팅을 넣기로 했으므로 실패 확률이 올라갔다.
→ 대응은 9번 일정과 10번 폴백 참조. **P0 먼저, BLE는 나중에, 자정 전에 영상 1차.**

### 창업·사업화 가능성 (15점) — 목표 고객과 수요 및 확장 가능성

| 단계 | 고객 | 가격 | 근거 |
|---|---|---|---|
| 지금 | 참가자 | 무료 | 원가 1인 20~30원 |
| 1차 | **행사 주최자** | 행사당 30~50만원 | Converve €3,400~7,900, b2match €699/yr, 그리팅 월 4.5~18만원 |
| 2차 | 대학 사업단 | 학교당 연 300~500만원 | 공주대 캡스톤 팀당 100만원 × 약 50팀 |
| 3차 | 기업 HR | ₩6,000/인/월 앵커 | 레몬베이스·클랩·잔디가 전부 이 가격에 수렴 |

**지불자가 명확하다.** 행사 네트워킹 업체 전부가 주최자에게 €700~$18,000를 받고 참가자에겐 한 곳도 안 받는다.

**지표를 바꾼다** — **참가자 리텐션은 지표가 아니다. 주최자 재도입이 지표다.**
Mentimeter도 참가자 리텐션 없이 2025년 순매출 SEK 598M을 흑자로 냈다.

**확장 근거** — 국내 신입 퇴사 사유 1위가 **조직·직무 적응 실패 49.1%**(경총). 적응은 첫 관계에서 갈린다.

### 발표 및 질의응답 (15점)

5분 대본과 예상 질문 답변은 `scenario.md`. 시연 영상 80초.
**두 시에는 자야 한다.** 준비한 답이 아무리 좋아도 못 자면 안 나온다.

# 5. 기능

## P0 — 없으면 제품이 아님
1. QR·코드 입장 (3초, 계정 없음)
2. 상태 선택 + 한 줄 (30초)
3. 방 목록 (집계 + 카드, 실시간)
4. **AI 접점 매칭 + 카드** (상보 관계 + 근거 + 첫마디)

## P1 — 점수에 직결
5. **BLE 1:1 채팅** — 서버를 거치지 않는 대화
6. 운영진 대시보드 (숫자 하드코딩 허용)
7. 정보 공개 범위 표시 (넘어간 것 / 안 넘어간 것)
8. 접점 없을 때 화면

## P2 — 여유 있으면
상태 세트 전환 · 반응 버튼 · 만료 실동작 · 구역 선택

## 범위 밖
로그인 · DB 영속화 · 푸시 · 일상 모드 · iOS 네이티브 · 그룹 채팅 · 메시지 저장

> **채팅 원칙**: 대화는 **만나기 위한 것**이지 만남을 대체하는 게 아니다.
> 메시지를 저장하지 않고, 연결이 끊기면 사라지고, 행사가 끝나면 전부 없어진다.

## 화면 6개
입장 → 상태 설정 → 방 목록 → 접점 카드 → BLE 채팅 → (별도) 운영진 대시보드

# 6. 기술 스택

| 층 | 선택 | 비고 |
|---|---|---|
| **프론트** | **React + Vite** | 캐패시터와 가장 흔한 조합 |
| **앱 래핑** | **Capacitor** | 웹 코드 그대로 안드로이드 빌드. 웹 폴백 무료로 확보 |
| **BLE** | `@capgo/capacitor-bluetooth-low-energy` | peripheral 지원. 안 되면 아래 대안 |
| **백엔드** | **FastAPI + uvicorn** | SSE 몇 줄, OpenAI SDK 그대로 |
| **상태 저장** | **메모리 dict. DB 없음** | 저장하지 않는 게 약속이 아니라 구조 |
| **실시간** | **SSE** | 웹소켓 불필요 |
| **LLM** | **ai.cs.kookmin.ac.kr** | OpenAI 호환. base_url만 교체 |
| **배포** | **OCI + Caddy + nip.io** | 터널 불필요, 인증서 자동 |

## BLE 플러그인 — 순서대로 시도
1. **`@capgo/capacitor-bluetooth-low-energy`** — peripheral 모드 지원. npm 공개
2. 안 되면 **`@capacitor-community/bluetooth-le`(central) + `cordova-plugin-ble-peripheral`(광고)** 조합. 캐패시터는 코르도바 플러그인을 그대로 쓴다
3. **Capawesome은 유료** — Insiders 라이선스 필요. 제외
4. `@capacitor-community/bluetooth-le` 단독은 **central 전용이라 광고 불가.** 제외

## BLE 채팅 설계
- **GATT 연결 방식.** 광고 패킷(31바이트)으로는 불가능
- 한쪽이 GATT 서버(peripheral), 다른 쪽이 센트럴로 연결해 특성에 write, 받는 쪽은 notify
- **MTU 협상**으로 517바이트까지. 한글 약 160자. 채팅 메시지로 충분
- 권한: 안드로이드 12+ `BLUETOOTH_SCAN`, `BLUETOOTH_ADVERTISE`, `BLUETOOTH_CONNECT`
- **밤을 잡아먹을 범인은 `status 133`.** 기기마다 다르고 재현이 안 된다. 타임박스 필수

## 아이폰 대응
같은 웹 주소로 들어오면 **BLE만 없이 전부 동작**한다. 국내 20대 아이폰 53%를 버리지 않는다.
심사위원이 아이폰이어도 시연에 참여할 수 있다.

# 7. 배포

> **2026-09-19 정정.** 아래 "Caddy + nip.io"는 초기 계획이었고 **폐기했다.**
> 실제로는 이미 운영 중인 OCI 서버(다른 프로젝트가 Nginx+Coolify로 돌아가는 곳)가
> 있어서, 새로 인스턴스를 만들지 않고 **그 위에 새 서브도메인으로 얹었다.**

## 실제 배포 (지금 이거)

**주소: `https://bside-api.sungblab.com`** — 이미 Nginx + Let's Encrypt 인증서까지 설정 완료.

**백엔드가 지켜야 할 규칙 딱 하나**: 앱을 **`127.0.0.1:8100`에서만** 리스닝시킬 것.
외부에 직접 노출하지 않는다 — nginx가 HTTPS를 처리하고 그 포트로 내려보낸다.
`0.0.0.0:8100`으로 열어도 동작은 하지만, 이미 도는 다른 서비스들과 같은 서버라
관례상 로컬호스트에만 묶는다.

**SSE는 이미 준비돼 있다.** `proxy_buffering off` · `proxy_read_timeout 24h`를
nginx 설정에 넣어뒀다 — `GET /room/{code}/stream`을 그대로 열면 된다. (아래 "SSE가
프록시에서 막힌다"는 옛 Caddy 계획 때 걱정이었고, 지금 nginx 설정으로 이미 해결됨.)

**로컬에서 뜨는지 확인하는 법** (배포 서버에서):
```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8100/   # 앱이 응답하는지
curl -s -o /dev/null -w '%{http_code}\n' https://bside-api.sungblab.com/  # 외부에서 확인
```
502가 나오면 앱이 8100번에서 아직 안 뜬 것. 그 외 나머지는 앱 쪽 문제다.

**주의**: 이 서버는 다른 팀원 개인 서버이고 다른 프로젝트도 같이 돈다.
컨테이너·볼륨은 반드시 `bside` 접두어를 붙여 구분하고, 다른 서비스의
Nginx 설정·Docker 볼륨·systemd 유닛은 절대 건드리지 않는다.

<details>
<summary>폐기한 초기 계획 (참고용으로만 남김)</summary>

**OCI + Caddy + nip.io**

## 함정 3개 (모르면 각각 한 시간씩 날아간다)

**1. 방화벽이 두 겹이다**
콘솔 보안 목록에 인그레스를 열어도 안 된다. 우분투 이미지는 인스턴스 안 iptables에 DROP 규칙이 기본이다.
```bash
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save
```

**2. HTTPS가 사실상 필수다**
안드로이드 9+ 평문 차단, 웹 카메라(QR)는 HTTPS에서만 열린다.
도메인이 없으면 `<IP>.nip.io`를 쓰면 된다. Let's Encrypt도 발급된다.
```
1.2.3.4.nip.io {
    reverse_proxy localhost:8000
}
```

**3. SSE가 프록시에서 막힌다**
nginx는 `proxy_buffering off`가 필요하다. **Caddy는 기본으로 정상.** 이게 Caddy를 권하는 이유다.

# 8. 협업

**브랜치 + PR**

## 브랜치 규칙
```
main            ← 항상 동작하는 상태 유지
  feat/server   ← 백엔드
  feat/web      ← React 화면
  feat/ble      ← Capacitor + BLE
  feat/ai       ← 프롬프트·매칭
```

## 규칙 다섯 개
1. **PR은 작게, 리뷰는 빠르게.** 해커톤에서 리뷰 대기가 길면 브랜치의 의미가 없다. **30분 안에 머지**를 기본으로
2. **파일 소유를 나눈다.** 같은 파일을 두 사람이 만지지 않게 디렉터리를 먼저 가른다. 충돌이 가장 큰 시간 낭비다
3. **인터페이스를 먼저 고정한다.** `protocol.md`의 JSON 모양만 지키면 서로 안 기다린다. 화면은 더미 JSON으로, 백엔드는 목 데이터로 먼저 시작
4. **main이 깨지면 즉시 되돌린다.** 고치려 들지 말고 revert 먼저
5. **커밋 메시지는 한 줄이면 충분하다.** 컨벤션에 시간 쓰지 않는다

## 역할 분담
팀에서 정하기로 함. 다만 **발표 자료와 시연 영상을 맡을 사람을 반드시 정할 것.**
개발만 하다가 새벽에 발표 자료를 시작하면 15점이 날아간다.

## 공유 문서
| 파일 | 용도 |
|---|---|
| `spec/MASTER.md` | 이 문서. 전체 그림 |
| `spec/protocol.md` | JSON 규격. **이것만 지키면 서로 안 기다린다** |
| `spec/prompts.md` | LLM 프롬프트 전문 + 검증기 규칙 |
| `spec/scenario.md` | 시연 대본 + 5분 발표 대본 + 예상 질문 |
| `spec/PRD.md` | 기능 명세 |
| `spec/roadmap.md` | 버전 로드맵 |
