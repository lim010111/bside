### 이 순서를 관통하는 한 가지 판단

**프로토타입은 버리는 목업이 아니라 참조 구현이다.**

891줄 안에 화면 구성, 카피, 만료 계산, 빈 상태, 오류 상태, 긴 텍스트 처리가
전부 들어 있고 이미 디버깅까지 끝났다. 처음부터 다시 설계하면 그 판단을 전부 다시 한다.

**베낀다. 재설계하지 않는다.** CSS는 거의 그대로 옮기고, 함수는 컴포넌트로 옮긴다.

## 1. 원칙 셋

1. **백엔드를 기다리지 않는다.** 목 데이터로 화면을 전부 끝내고 마지막에 갈아끼운다.
2. **시연 경로부터 만든다.** 영상 8컷이 지나가는 순서대로 만든다. 예외 화면은 그다음이다.
3. **자정에 영상을 찍을 수 있는 상태**가 모든 결정의 기준이다. 자정 전에는 BLE도 Capacitor도 손대지 않는다.

## 2. 먼저 못박을 결정 (고민하지 말 것)

| 항목 | 결정 | 이유 |
|---|---|---|
| 언어 | **JavaScript** (TS 아님) | 타입 정의 쓸 시간에 화면을 만든다. 데이터 모양은 목 파일 하나로 고정된다 |

| 아이콘 | 프로토타입 **SVG 스프라이트 그대로** | `index.html`에 심고 `<use href="#i-...">` 유지 |

### 0단계 · 셋업 (30분)

```bash
npm create vite@latest web -- --template react
cd web && npm i
```

그다음 **순서대로** 세 가지만 한다.

1. `prototype/index.html`의 `<style>` (10~169줄) → `src/index.css`에 통째로 붙인다. 한 줄도 고치지 않는다.
2. 같은 파일 `<svg>` 스프라이트 (173~191줄) → `index.html`의 `<body>` 맨 위에 붙인다.
3. 폰트 `<link>` 2줄 (8~9줄) → `index.html`의 `<head>`에.

**끝난 기준**: `<h1 class="t-xl">테스트</h1>`가 다크 배경에 Wanted Sans로 뜬다.

### 1단계 · 데이터 계약 (30분) — **가장 중요한 단계**

화면을 만들기 전에 **데이터 모양부터 고정한다.** 이걸 건너뛰면 백엔드가 나온 뒤 화면을 다시 만든다.

```
src/api/
  shapes.js    # 주석으로 데이터 모양 기록 (protocol.md 1번 그대로)
  mock.js      # 목 구현. prototype의 SEED_HACK(388줄~)을 그대로 가져온다
  client.js    # 진짜 API. 함수 이름과 리턴 모양이 mock.js와 완전히 같아야 한다
  index.js     # import { api } — 환경변수로 mock/client 선택
```

```js
// src/api/index.js
import * as mock from './mock';
import * as client from './client';
export const api = import.meta.env.VITE_USE_MOCK === '1' ? mock : client;
```

다섯 함수만 있으면 된다. 이름과 리턴 모양을 지금 고정한다.

| 함수 | 리턴 |
|---|---|
| `getRoom(code)` | `{ title, when, aff, statusSet }` |
| `join(code, {nick, school, status, note})` | `{ id }` |
| `getMembers(code)` | `[{ id, nick, school, status, note, near, age }]` |
| `getMatch(code, id)` | `{ peer, reason, opener, score }` 또는 `null` |
| `heartbeat(code, id)` | `200` |

**끝난 기준**: `api.getMembers('KOSS26')`가 45명을 돌려준다. 이제 백엔드는 잊는다.

> **백엔드 담당에게 지금 보낼 것**: 위 표 그대로. 여기서 어긋나면 8단계에서 터진다.

### 2단계 · 입장 화면 (1시간)

참조: `prototype/index.html` 193~239줄(마크업), `renderPreview()` 562줄.

**미리보기 화면은 없다.** 닉네임·소속·상태·한 줄이 한 화면에 있고, 올려야 방이 열린다.

빠뜨리기 쉬운 것 넷:

- 인원수와 구성 띠는 보여주되 **남의 한 줄은 가린다** (올리는 게 입장료)
- 소속은 `room.aff.options`가 있으면 `<select>`, 없으면 `<input>` (행사마다 다르다)
- 검증 4종: 닉네임 / 소속 / 상태 / 한 줄. 빈 값마다 다른 문구
- **수정 모드**에서 방으로 돌아가는 길. 이거 없으면 막다른 길이 된다

**끝난 기준**: 입력 → 올리기 → 방 화면. 빈 값으로 누르면 해당 문구가 뜬다.

### 3단계 · 방 목록 (1.5시간) — 제일 큰 덩어리

참조: `renderRoom()` 649줄, `pcard()` 692줄, 마크업 240~256줄.

쪼개서 만든다.

```
RoomScreen
  ├─ RoomHeader      방 이름 + 인원
  ├─ Composition     색 띠 + 집계 + "방금 N명 들어옴"
  ├─ MyStatus        내 카드 (누르면 수정)
  └─ PeopleList
       ├─ GroupLabel   닿는 거리 N / 조금 떨어진 곳 N
       └─ PersonCard   ← 여기에 만료 실선
```

규칙 셋을 지킨다. 이게 디자인의 전부다.

1. **색은 상태를 뜻할 때만.** 카드당 색이 나오는 곳은 상태 라벨 하나
2. **근접은 색이 아니라 밝기로.** `near`면 배경 한 단계 밝게
3. **정렬은 시간 순.** 관련도 순으로 정렬하면 AI 없이 해결돼서 제품이 필요 없어진다

만료 계산은 그대로 가져온다:

```js
const ageOf  = p => p.age + (Date.now() - t0) / 1000;
const lifeOf = p => Math.max(0, 1 - ageOf(p) / 300);   // TTL 300초
const fadeOf = l => l > .45 ? 1 : .34 + (l / .45) * .66;
```

**끝난 기준**: 46명이 두 그룹으로 나뉘고, 카드마다 밑 실선 길이가 다르고, 아래로 갈수록 바랜다.

### 4단계 · 접점 시트 (1시간) — 심사에서 제일 오래 보는 화면

참조: `openSheet()` 741줄.

**여기만 손을 더 댄다.** 나머지 화면과 완성도가 같으면 안 된다.

- 근거 블록: 내 한 줄 → ↓ → 상대 한 줄, `겹치는 단어 0개`, 강도 막대
- 첫마디는 따옴표 블록으로 크게
- 맨 아래 `상대에게 전해지는 건 이름과 이 한 줄뿐입니다` — 프라이버시 주장이 눈에 보이는 자리
- **접점 없을 때 화면**도 같이 만든다. 시연에서 물어본다

**끝난 기준**: 시트가 올라오고, 근거가 읽히고, 접점 없을 때도 안 깨진다.

## 6. 지금 막아야 할 것 — 상태 코드가 어긋나 있다

| 문서 | 코드 |
|---|---|
| `spec/protocol.md` | `NEED_HELP` `CAN_HELP` `BREAK` `FOCUS` `ONBOARDING` |
| `prototype/index.html` | `LOOKING_FOR` `CAN_SHARE` `FIRST_TIME` `OPEN` |

**둘이 다르다.** 프론트와 백엔드가 각자 다른 걸 보고 짜면 8단계에서 붙지 않는다.

→ **프로토타입의 4종으로 통일할 것을 권한다.** 화면·카피·색이 이미 4종 기준으로 잡혀 있고,
디자인 문서의 색 토큰도 4개다. 백엔드 담당과 **지금** 한 줄로 합의하고 `protocol.md`를 고친다.

## 7. 하지 말 것

- **CSS 정리하기** — 이미 실기기에서 검증된 값이다
- **TypeScript 도입** — 데이터 모양은 목 파일 하나로 고정된다
- **컴포넌트 라이브러리 / Tailwind** — 확정된 디자인을 라이브러리와 싸우게 만든다
- **라우터 · 상태관리 라이브러리** — 화면 4개다
- **자정 전에 BLE·Capacitor 만지기** — 원칙 1번이 깨진다
- **목록을 관련도 순으로 정렬** — AI 없이 해결돼서 제품 논리가 무너진다
- **백엔드 기다리기** — 1단계를 했으면 기다릴 이유가 없다
