# 기존 프론트에서 구현할 변경

React·Vite·JavaScript/JSX, 기존 CSS·컴포넌트·Context/reducer 구조를 유지한다. 현재 화면은 이전 정책의 mock이며 **[MVP 개발 기준](../docs/development-contract.md)과 [API 계약](../docs/api-contract.md)** 으로 동작을 갱신한다. TypeScript 전환·UI 라이브러리 교체·새 scaffold는 선행 작업이 아니다.

| 파일·경계 | 현재 코드 | 구현할 동작 |
| --- | --- | --- |
| `screens/Entry.jsx` | 닉네임·소속·상태·140자 한 줄 | 닉네임·자기소개·찾는 사람. 입력 시 같은 방 참가자에게 보이는 범위 안내. 두 원문 수정 가능 |
| `App.jsx`, `api/index.js` | 입장 전에도 전체 mock 목록 조회 | 공개 방 안내·세션 복원 후 분기. 입력 완료 전 개인 목록 요청 안 함. 서버 거부도 별도로 구현 |
| `api/shapes.js`, `mock.js`, `client.js` | 이전 필드·고정 추천·실제 API stub | API 계약의 공통 예시·상태·오류를 사용. mock과 실제 응답 모양을 같게 유지 |
| `screens/Room.jsx` | 5분 필터·시간순·near 거리 그룹 | 같은 방 전체의 서버 추천 순서. 낮은 순위·미평가도 표시. 가짜 거리·자연 만료 제거 |
| `components/PersonCard.jsx` | 정보 표시만, 클릭 불가 | 모든 참가자 배너에서 해당 사람의 상세 열기 |
| `TouchpointSheet.jsx` 등 상세 | 고정 한 명·0.85·자동 첫마디 | 선택한 상대의 두 원문·조회자별 이유·추천 대기/실패 상태. 숫자 점수 없음. 바로 채팅 |
| `state.jsx` | 수정 뒤 `matchChecked` 유지 | 입력·후보 버전 변경 시 오래된 순위·이유 폐기하고 갱신 |
| 세션·참여 상태 | sessionStorage·300초 복원 | 영속 브라우저 세션 + `/me`. 앱을 닫아도 유지. 중단·재개 UI와 상태별 권한 반영 |
| `lib/bleChat.js`, `screens/Chat.jsx`, 대화 목록 | 고정 메시지·자동 답장·뒤로 가면 배열 비움 | API를 통한 대화 목록·이력·전송·재시도. 서버 메시지 순번으로 합침. 양쪽 실제 답장 |
| SSE·재접속 | 미구현 | `ready` 후 목록·이력 조회, 재연결·화면 복귀·보완 조회. 수신 이벤트는 이력 재조회 신호 |
| `screens/Ended.jsx` | 로컬 예정 시각·삭제 완료 문구 | 서버 `room.closed`·`ROOM_CLOSED`로 전환. 늦은 응답 무시·개인 캐시 제거. 이용 종료만 안내 |
| `screens/Dashboard.jsx` | 고정 집계 | 보류 자산. MVP 탐색·시연에 필수로 노출하지 않음 |

`lib/expiry.js`의 표시 보조 코드는 참가자 삭제 규칙으로 재사용하지 않는다. 상태 프리셋·거리·만료를 데이터 계약에 다시 넣지 않는다. 디자인 토큰은 [기존 시각 자산](design.md)에서 재사용하되 제품 행동은 현재 계약을 따른다.

## 연결 순서와 확인

1. T00에서 mock·JSDoc을 공통 예시로 바꾸고 실제 `/api` 연결 위치를 정한다. 현재 기본 mock을 껐을 때 실제 제품 API가 생기는 것은 아니다.
2. T01에서 입력·목록·상세·중단/재개 화면을 맞추고 T05에서 실제 두 브라우저 입장을 연결한다.
3. T06에서 채팅 전송·이력·복원을 연결하고 T07에서 실제 추천·종료를 합친다.
4. V01~V12 중 담당 조건을 확인한다. `npm run build`·`npm run lint`만으로 브라우저 복원·기기 간 통신을 통과 처리하지 않는다.

종료·중단·실패 상태는 서버 응답에 따라 표시한다. 존재하지 않는 BLE 연결, ‘기록이 남지 않는다’, 가상 참가자 수·고정 추천을 실제 상태로 안내하지 않는다.
