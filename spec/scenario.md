# 시연 시나리오

시간표·준비물·완료 조건은 [검증과 5분 시연 계획](../docs/validation.md)을 따른다. **실제 두 사용자의 답장과 같은 소개·다른 의도의 추천 비교**가 핵심이다.

1. 두 브라우저가 QR·링크로 같은 행사에 들어가 각각 자기소개와 찾는 사람을 입력한다.
2. A가 추천 목록에서 B의 배너를 누른다. B의 자기소개·찾는 사람·A에게 추천한 이유를 확인한다.
3. A가 바로 메시지를 보내고 B가 실제 기기에서 답장한다. 자동 답장을 실제 교류로 보여주지 않는다.
4. A의 자기소개를 유지한 채 교류 의도만 바꾼다. E01/E02에 맞춰 추천과 이유가 어떻게 달라지는지 실제 모델 결과로 비교한다.
5. 복원·중단/재개·운영자 종료는 검증 기록이나 짧은 백업 영상으로 보완한다. 5분 안에 모든 경계를 직접 시연하려고 흐름을 늘리지 않는다.

인원·추천·응답은 가상 입력과 실제 수행을 구분한다. 고정 대시보드 숫자·모델 자체 점수·버튼 클릭만으로 교류 증가를 주장하지 않는다. 두 사람이 각각 메시지를 보낸 대화와 실제 대면도 구분한다.

발표 배점과 자료 마감은 [주최 측 안내](../docs/hackathon-brief.md)를 따른다. 운영진은 도입 고객 후보이고 참가자는 사용자라는 가설을 설명하되 아직 검증하지 않은 사업 성과를 주장하지 않는다.
