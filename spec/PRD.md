# MVP 제품 요구 — BLE 기반 주변 교류

2026-09-20. 제품 결정은 [B1~B14](../docs/product-direction.md), 행동의 원본은 [개발 기준](../docs/development-contract.md)이다. 제품 흐름은 사용자 최종 합의가 완료됐으며 BLE 구현·실기기 검증 완료를 뜻하지 않는다.

## 핵심 흐름

1. Android 앱에서 회원가입 없이 닉네임·자기소개·교류 의도를 입력한다. 같은 설치에서 복원하며 수정할 수 있다.
2. 발견을 켜면 직접 끌 때까지 참여 의사를 유지한다. 몇 분 이상 함께 머무는 상대를 중심으로 BLE 발견을 검증한다.
3. 유효하게 발견된 참여자 전체를 추천 순서로 본다. 상세에 자기소개·교류 의도·조회자를 위한 추천 이유를 표시한다. 숫자 점수는 보여주지 않는다.
4. 적합한 새 상대는 앱 밖에서도 자동 추천 알림으로 알린다. 실제 문제가 발생하면 해당 범위를 재검토한다.
5. 별도 요청·수락 없이 첫 메시지를 보낸다. 상대가 답장·대화 지속 여부를 정한다.
6. 이미 시작한 대화는 거리 이탈·발견 OFF 뒤에도 송수신·복원한다. 새 상대에게 첫 메시지를 보낼 때에는 현재 발견·참여 조건이 필요하다.

## 이번 범위

인터넷이 필요하고 Android 간 검증부터 시작한다. 행사에서도 같은 흐름을 사용하며 행사 방·QR 입장·운영자 종료는 없다. 시연 데이터와 일반 데이터에 같은 정책을 적용하고 시연 종료 특별 삭제를 두지 않는다.

사용자 입력·양쪽 의도 고려·Promptfoo 선택은 유지한다. 원문 없는 사실을 지어내지 않으며 AI 실패에도 목록·채팅은 동작한다. 낮은 평가만으로 후보를 제거하지 않는다.

## 후속 범위

iPhone·교차 OS, 몇 초의 스침 포착 보장, 장시간 배터리 최적화, 정확한 거리 표시, 완전 오프라인, 재설치·기기 간 복원, 사진·파일·읽음 등 부가 채팅 기능은 이번 선결 조건이 아니다. 요청·수락·거절/재요청 게이트는 B13으로 폐기했다. 장기 데이터 보관 정책은 동일 데이터 원칙 아래 후속 설계한다.

## 구현 상태

React/Vite mock 화면과 FastAPI·Redis 기반을 보유한다. 선택한 Capacitor·Kotlin 계층과 제품 API·실제 AI·두 사용자 통신은 구현 전이다. [Android 구성](../docs/android-design.md), [검증 계획](../docs/validation.md)을 따른다.
