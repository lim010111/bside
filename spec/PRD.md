# Bside — PRD

> 코쓱톤 2026 · 작성 2026-09-19 · 제출 2026-09-20 12:00

---

## 1. 개요

**Bside** — 행사장에서 옆에 있는 사람과 연결되는 앱.
**Connect with who's beside you.**

이름의 이중 의미
- **Beside** — 옆에 있는 사람
- **B-side** — 음반의 뒷면. **행사의 A면이 발표라면 B면은 사람이다.** 그리고 기억에 남는 건 대개 B면이다

---

## 2. 문제

밋업이나 컨퍼런스에 혼자 가본 사람은 안다.

- 네트워킹 시간 30분이 주어진다
- 아는 사람끼리 뭉치고, 혼자 온 사람은 음료 테이블 옆에서 폰을 본다
- 명함 몇 장은 받지만 왜 이 사람인지 모른다
- 30분이 끝난다

**말을 걸 용기가 없어서가 아니다. 누구에게 왜 걸어야 하는지를 모르기 때문이다.**

근거
- Converve 벤치마크: **주최자의 15%만** 자사 네트워킹이 매우 효과적이라 평가
- Brella는 **참가자 30%가 미팅을 예약하면 실패**로 본다. 대표 사례 TechBBQ조차 앱 채택 58%, 수락률 39%
- 즉 **돈 내고 전용 앱을 깔게 해도 절반이 안 쓴다.** 무겁기 때문이다

---

## 3. 목표 사용자

| | 누구 | 원하는 것 |
|---|---|---|
| **주 사용자** | 행사 참가자 (혼자 온 사람) | 말 걸 상대와 이유 |
| **구매자** | 행사 주최자·운영진 | 참가자 만족도를 숫자로 증명 |

**돈은 주최자가 낸다. 참가자는 무료.**
행사 네트워킹 업체 전부가 주최자에게 €700~$18,000를 받고 참가자에겐 한 곳도 안 받는다.

---

## 4. 핵심 흐름

```
주최자가 QR 띄움
   ↓
참가자 스캔 → 앱 진입 (닉네임·소속만)
   ↓
상태 한 줄 설정  ← 30초 안에 끝나야 한다
   ↓
방 목록 — 같은 행사 사람들의 상태
   +  BLE로 잡힌 사람은 "가까움" 표시
   ↓
AI가 상보 관계 발견 → 카드 + 첫마디
   ↓
가서 말을 건다  ← 앱 안에서 채팅하지 않는다
   ↓
행사 끝 → 방 소멸. 참가자에겐 아무것도 남지 않음
```

## 5. 기능 명세

### P0 — 없으면 제품이 아님

| ID | 기능 | 수용 기준 |
|---|---|---|
| F1 | QR·코드로 방 입장 | 스캔에서 입장까지 3초 이내. 계정 없음 |
| F2 | 상태 선택 + 한 줄 입력 | 프리셋 4~5종 + 자유 입력 140자. 전체 30초 이내 |
| F3 | 방 목록 | 상단 상태별 집계, 아래 카드 리스트, 실시간 갱신 |
| F4 | **AI 접점 매칭 + 카드** | 상보 관계 + 근거 + 첫마디. 강도 0.6 미만은 알림 안 함 |

### P1 — 점수에 직결

| ID | 기능 | 비고 |
|---|---|---|
| F5 | 운영진 대시보드 | 입장률, 접점 수, 대화 시작 수, 인기 주제. **숫자 하드코딩 허용** |
| F6 | 정보 공개 범위 표시 | 넘어간 것 / 안 넘어간 것 두 컬럼 |
| F7 | 접점 없을 때 화면 | 억지 매칭 대신 "아직 없다"고 말함 |
| F8 | **BLE 근접 표시** | 잡히면 "가까움" 뱃지. **안 잡혀도 방 기준으로 정상 동작** |

### P2 — 여유 있으면

F9 구역 선택 · F10 상태 세트 전환(해커톤형/밋업형) · F11 좋아요·괜찮아요 반응 · F12 상태 만료 실동작

### 범위 밖 (하지 않음)

**채팅** · 로그인·회원가입 · DB 영속화 · 푸시 · 일상 모드 · iOS 네이티브

> **채팅을 넣지 않는 이유**: 넣는 순간 근거리 채팅 앱이 된다.
> "앱에서 채팅하지 않고 현실에서 말을 건다"가 차별점이다.

## 6. 화면

1. **입장** — QR 스캔 → 닉네임, 소속
2. **상태 설정** — 프리셋 + 한 줄
3. **방** — 집계 + 카드 목록
4. **접점 카드** — 상대, 근거, 첫마디, 반응 버튼
5. **운영진 대시보드** — 별도 진입

---

## 7. 기술

**플랫폼**: 안드로이드. QR 입장은 웹으로도 열어 아이폰 폴백 확보(권장)

**스택 — 결정 대기**

| 안 | BLE 광고 | 화면 | 아이폰 폴백 | 리스크 |
|---|---|---|---|---|
| **순수 Kotlin** | ✅ 표준 API, 확실 | Compose로 직접 | ❌ | 화면 작업량 |
| **Capacitor + 비콘 방식** | 광고 불필요(스캔만) | 웹 재사용 | ✅ | 사람 대 사람 근접 불가, 구역만 |
| Capacitor + Capawesome | ✅ peripheral 지원 | 웹 재사용 | ✅ | 유료 여부 확인 필요 |
| React Native | △ 라이브러리가 초기 단계 | JS | ✅ | 밤샘 디버깅 위험 |

> `@capacitor-community/bluetooth-le`는 **central 전용이라 광고를 못 한다.** 이 안은 제외.

**서버**: 메모리 딕셔너리만. **DB 없음.** SSE 또는 5초 폴링
**LLM**: `ai.cs.kookmin.ac.kr` 게이트웨이 (OpenAI 호환)

## 8. AI 레이어

세 곳에서 쓴다. 프롬프트 상세는 `spec/prompts.md`.

1. **한 줄 → 구조화** — 자유 입력에서 태그·유형 추출. 폼을 없애는 장치
2. **상보성 판정** ← **핵심.** 찾는 사람과 해본 사람을 잇는다
3. **첫마디 생성** — 맥락 반영한 실제 문장

**AI에게 맡기지 않는 것** (발표에서 명시): 같은 방 필터, 만료 검사, 중복 알림 차단, 강도 임계값, 시간 계산

**왜 AI여야 하는가**
"배포·CI 경험자 찾음"과 "작년에 도커 CI 구축해봄"은 **겹치는 단어가 0개다.**
임베딩 유사도는 오히려 둘 다 막힌 사람을 이어준다. 상보성은 유사도의 반대다.

**호출 수 관리**: 20명이면 쌍이 190개. 코드로 후보를 좁혀(상태가 서로 반대인 쌍만) 보통 5회 이하로 호출.
**원가**: 1인당 약 20~30원

## 9. BLE 설계

- **뿌리는 것은 짧은 ID뿐.** 광고 페이로드 31바이트 제약. 한글 여섯 자면 끝난다
- 내용은 서버에서 ID로 조회
- **BLE는 입장 수단이 아니라 근접 표시.** 안 잡히면 방 기준으로 정상 동작해야 한다
- 권한: 안드로이드 12+ `BLUETOOTH_SCAN`, `BLUETOOTH_ADVERTISE`
- 우회안: 비콘 하나를 두고 참가자는 스캔만 → 구역 판정

---

## 10. 비기능 요구

**프라이버시** — 계정 없음. 위치정보 미수집(GPS·와이파이 AP 안 씀 → **위치정보법 신고 대상 아님**).
서버 DB 없음. 상태는 하트비트 5분 끊기면 만료. 행사 종료 시 방 전체 소멸.
경계를 넘는 것은 도출된 접점뿐, 원본 프로필은 넘지 않는다.

**보안** — 타 사용자의 자유 입력을 시스템 프롬프트에 넣지 않는다. 데이터 블록으로 감싸고 지시문은 무시.

**성능** — 입장 3초, 상태 저장 30초 이내, 접점 카드 10초 이내.

## 11. 성공 지표

**참가자 리텐션은 지표가 아니다. 주최자 재도입이 지표다.**
Mentimeter도 참가자 리텐션 없이 2025년 순매출 SEK 598M을 흑자로 냈다.

| 지표 | 목표 |
|---|---|
| 입장률 | 행사 참가자의 50% 이상 |
| 상태 설정률 | 입장자의 80% 이상 |
| 대화 시작 | 접점 카드의 30% 이상에서 "좋아요" |
| **주최자 재도입** | 다음 행사에도 쓰겠다 |
